# ASSUMPTIONS — qhud

> Status: living · Date: 2026-09-07 · Owner: chquandogong
> Rewritten for v0.6.1. The previous list dated from v0.4.0 and carried a
> stale dependency revision, a single-platform premise that v0.6.0 broke, a
> "never persists" claim that was never true of qhud's own state, and a
> relative date ("verified today") that cannot be read a month later. Dates
> here are absolute, always.

| ID  | Assumption                                                                                                                                                                                              | Status                                    | Evidence / revisit trigger                                                                                                                                                                                                                                                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | The primary **terminal-monitoring** target is one GNOME Wayland workstation. Windows x64 is a supported **account-usage** target with no pane observation. Other desktops are best-effort; macOS is out | accepted, revised 2026-09-07              | v0.6.0 added a native Windows target with its own CI job, release artifact and ops guide. Revisit if KDE or wlroots users appear, where a layer-shell path would be worth adding                                                                                                                                                                |
| A2  | Mutter honors `_NET_WM_STATE_BELOW` and `_STICKY` for XWayland windows                                                                                                                                  | verified 2026-09-07                       | Re-verified on the published v0.6.0 Linux asset: `_NET_WM_STATE` carried BELOW, STICKY, SKIP_TASKBAR and SKIP_PAGER with `_NET_WM_DESKTOP` at `0xFFFFFFFF`. Originally from the feasibility spikes. Linux only                                                                                                                                  |
| A3  | Both monitors run at scale 1, so XWayland fractional-scaling blur does not apply                                                                                                                        | verified 2026-09-07                       | eDP-1 2560×1600 and HDMI-1 3840×2160, both scale 1. Revisit if fractional scaling is enabled: GNOME 46 blurs XWayland, GNOME 47+ improves it (R3)                                                                                                                                                                                               |
| A4  | The qmonster TUI owns everything under its own directory; a second writer would race its database                                                                                                       | accepted by design                        | `NoopSink` and `SilentNotify` (D-004). qhud persists **its own** state elsewhere — the registry, the fetch store, and window geometry — all under the qhud config directory, written temp-then-rename. The invariant is "no writes under `~/.qmonster`", not "no writes at all"                                                                 |
| A5  | qmonster's library API at the revision pinned in `src-tauri/Cargo.toml` is the contract; upstream may drift                                                                                             | pinned                                    | Do not restate the revision in prose — the previous version of this row named a revision that had been superseded for a month. Bump deliberately and re-run the contract tests in `view.rs`. Windows consumes the same revision plus a checked-in patch, applied only for that platform's Cargo commands (D-020)                                |
| A6  | Alerting stays with the TUI and the providers; a widget that also notified would double-fire                                                                                                            | accepted                                  | `SilentNotify`                                                                                                                                                                                                                                                                                                                                  |
| A7  | The demo payload mirrors the design mockup closely enough to serve as the visual-parity fixture                                                                                                         | accepted, narrowed 2026-09-07             | Still true as a fixture, and it exercises the production rollup. The other half of the original assumption — that demo data is an acceptable stand-in when no multiplexer is reachable — was **withdrawn** in v0.6.0: a mux-less start now shows real accounts, and demo requires `--demo` (D-005)                                              |
| A8  | `visibleOnAllWorkspaces` and `alwaysOnBottom` are honored on the X11 backend                                                                                                                            | verified 2026-09-07                       | Re-asserted in code after the window is realized and after every layer flip, and confirmed by `xprop`. No equivalent claim is made for Windows, and none should be invented                                                                                                                                                                     |
| A9  | The footer clock repaints every second, so a byte-identical pixel strip 28 s apart means the compositor is not presenting                                                                               | load-bearing, unverified as an assumption | This is the frame guard's whole premise (D-017). If the footer ever stops ticking for a legitimate reason, the guard produces false positives and will hide-and-show a healthy window. Revisit if the footer's content becomes conditional                                                                                                      |
| A10 | Hide-and-show resumes painting for a frozen window                                                                                                                                                      | verified once, live, 2026-08-13           | Proven on an actually frozen instance, and 28 field freezes have since healed at that rung. The **second** rung — re-exec — has never fired in the field, so it is covered by unit tests only                                                                                                                                                   |
| A11 | The provider CLIs keep their account identity in cleartext at documented paths                                                                                                                          | accepted                                  | Claude's config file, Codex's `auth.json` account id, agy's active Google account (D-013). Paths are now environment-overridable, so the assumption is about the field names, not the locations. Revisit if a provider moves identity into a keyring — which is already true of agy's live token, and is why agy multi-account is unimplemented |
| A12 | The active Codex login's workspace pool is the same pool its pane statusline reports                                                                                                                    | accepted                                  | Why that workspace merges into the account row instead of rendering a second, clock-skewed copy of the same weekly window (v0.5.0). Revisit if Codex ever reports a pane pool distinct from the account pool                                                                                                                                    |
| A13 | The Edge WebView2 Runtime is present on any Windows target                                                                                                                                              | required, not verified by qhud            | Stated as a prerequisite; the widget does not detect or install it (R15). Revisit if a Windows user reports a silent failure to start                                                                                                                                                                                                           |
| A14 | Provider wire formats are **not** stable, and any integer-typed field may arrive as something else                                                                                                      | accepted the hard way, 2026-09-01         | The inverse of an assumption, recorded because assuming the opposite cost two days of dead refreshes. Every new integer-meaning field goes through the lenient reader, and no single optional field may fail a response (D-019, R14)                                                                                                            |
