# 보안 정책

<a id="supported-versions"></a>

## 지원 버전

보안 수정은 `main`에서 개발하고 가장 최근에 배포한 버전에 반영합니다. 가능하면 최신 릴리스나 현재 `main` 브랜치에서 의심되는 취약점을 재현해 주세요. 관리자가 별도로 알리지 않는 한 이전 릴리스는 지원하지 않습니다.

<a id="report-a-vulnerability-privately"></a>

## 취약점 비공개 신고

의심되는 취약점을 공개 이슈, 토론, 풀 리퀘스트에 올리지 마세요. GitHub의 [비공개 취약점 신고 양식](https://github.com/chquandogong/qhud/security/advisories/new)을 사용하세요. 이 양식을 사용할 수 없다면 세부 내용을 공개하지 말고 비공개 신고 경로가 복구될 때까지 기다려 주세요.

조사에 필요한 정보만 포함하세요.

- 영향을 받는 버전 또는 커밋, 운영체제, 설치 방법
- 영향과 문제를 일으키는 조건
- 합성 데이터를 사용한 최소 재현 절차 또는 개념 증명
- 이미 시험한 완화책이나 수정안

실제 인증 정보, `auth.json`, `.credentials.json`, 제공자 설정 디렉터리, 가리지 않은 진단 묶음 또는 다른 사람의 데이터를 보내지 마세요. 노출된 인증 정보는 신고 전에 폐기하세요.

관리자는 영업일 기준 3일 안에 신고를 확인하고 7일 안에 초기 판단을 전달하는 것을 목표로 합니다. 이는 최선의 노력 목표이며 서비스 수준을 보장하지 않습니다. 공개하기 전에 수정과 조율된 보안 권고를 위한 시간을 주세요.

<a id="scope-and-safe-research"></a>

## 범위와 안전한 조사

보안에 민감한 영역에는 로컬 인증 정보 탐색, 계정 및 스냅샷 소유권, 제공자 요청, WebView 렌더링 내용, 파일시스템 경로, 빌드 및 릴리스 파이프라인이 포함됩니다. 상위 AI 제공자의 취약점은 해당 제공자에게 신고하고, qhud가 노출을 만들거나 키운 경우에만 여기에도 신고하세요.

본인이 소유한 계정과 장비, 합성 또는 폐기한 인증 정보를 사용하고, 영향을 입증하는 데 필요한 최소한의 시험만 수행하세요. 다른 사람의 데이터에 접근하거나, 제공자 서비스를 방해하거나, 장비에 지속적으로 머무르거나, 사회 공학을 사용하지 마세요. 현재 이 프로젝트는 버그 바운티를 운영하지 않습니다.

일반 버그와 지원 요청은 [SUPPORT.md](SUPPORT.md)를 따르세요.
