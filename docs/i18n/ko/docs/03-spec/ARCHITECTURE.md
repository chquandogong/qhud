# 아키텍처 — qhud

> 상태: 지속 갱신(v0.6.0 소스를 기준으로 전면 개정) · 날짜: 2026-09-07 · 담당: chquandogong
> SPEC(해야 하는 일) 및 DECISION_LOG(이렇게 구현한 이유)의 동반 문서입니다. 여기의 모든 설명은 `v0.6.1` 트리를 읽고 작성했으며 행 수와 테스트 수 역시 해당 트리의 값입니다.

<!-- qhud:anchor -->
<a id="1-what-qhud-is-structurally"></a>

## 1. qhud의 구조

단일 프로세스 Tauri v2 데스크톱 애플리케이션입니다. Rust 코어가 관찰과 조회를 수행하고 번들러 없는 웹 프런트엔드가 렌더링합니다. qmonster 관찰 파이프라인의 **두 번째 프런트엔드**(D-001)로, 고정 Git revision의 크레이트를 라이브러리로 연결하며 qmonster 상태에 쓰지 않습니다.

하나의 코드베이스가 두 플랫폼을 지원합니다.

| | Linux(기준) | Windows x64 |
| --- | --- | --- |
| Webview | GTK 3를 통한 WebKitGTK | WebView2(Edge runtime 필수) |
| 데스크톱 계층 | XWayland + EWMH `_NET_WM_STATE_BELOW`/`STICKY`(D-003) | 네이티브 always-on-bottom |
| 터미널 창 | qmonster를 통한 tmux 또는 herdr(D-007) | **미구현** — 계정 사용 한도만 지원 |
| 프레임 가드 | 활성(GTK 픽셀 샘플링, D-017) | 컴파일에서 제외; WebView2에는 같은 장애가 없음 |
| 의존성 | 일반 Git 고정, 형제 checkout 불필요 | 형제 checkout에 명령 범위로 패치 |

Windows 이식은 데이터 처리용 두 번째 코드 경로를 추가하지 않았습니다. 공급자, 분석, 병합, 렌더링을 공유하며 경로 해석, 프로세스 실행, 프레임 가드만 플랫폼별로 구분합니다.

## 2. 프로세스와 스레드 모델

`main()`은 다음 순서로 실행됩니다.

1. 스레드가 생기기 전에 **Linux 전용 환경을 강제합니다**. 설정되지 않았을 때 설정하는 세 쌍과 각각의 우회 옵션이 있습니다. `GDK_BACKEND=x11`(`QHUD_NO_X11_FORCE`), `WEBKIT_DISABLE_DMABUF_RENDERER=1`(`QHUD_KEEP_DMABUF`), `WEBKIT_DISABLE_COMPOSITING_MODE=1`(`QHUD_KEEP_COMPOSITING`)입니다. 빈 값을 포함해 값이 존재하면 설정된 것으로 봅니다. Windows에는 이 블록 전체가 없습니다.
2. **Argv 사전 처리.** 진단 및 전달용 플래그를 Tauri나 GTK 초기화 전에 처리하므로 진단 실행은 창을 만들지 않습니다. `--respawned`는 단일 인스턴스 가드가 재실행을 흡수하지 않도록 먼저 1.5초 기다립니다.
3. **Tauri builder** 등록 순서: argv 전달 채널을 겸하는 단일 인스턴스 플러그인, 다섯 명령, window-state 플러그인, `setup`입니다.
4. **`setup`**: `main` 창을 가져옵니다(레이블은 빌드 시점 계약이므로 없으면 panic). `tauri.conf.json`이 이미 요청한 계층 상태를 다시 설정하고(X11은 창이 실제 생성된 뒤에만 따름), 트레이를 만들며(실패는 치명적이지 않고 기록함), 관찰 스레드를 시작합니다.
5. `run()` — 주 스레드가 GTK 또는 WebView2 이벤트 루프가 됩니다.

명시적으로 만드는 스레드는 관찰 루프 하나입니다. 창을 다루는 모든 작업은 주 스레드에서 실행하며 프레임 가드 역시 `run_on_main_thread`를 통해 샘플링을 전달합니다. `fetch_*` 명령은 `async`이며 Tauri 런타임에서 실행됩니다. 독립 실행 진단 플래그는 각각 자체 Tokio 런타임을 만들고 종료합니다.

## 3. 트레이와 계층 상태 머신

트레이 메뉴는 `Show / Hide`, 체크박스인 `Pin above windows`, `Reset position`, `Quit qhud`입니다. 고정 상태는 프로세스 전역 atomic 하나에 저장합니다. false는 기본 데스크톱 계층(keep-below), true는 위쪽 고정입니다.

계층을 적용할 때는 위/아래 전환과 함께 모든 작업 공간 고정, 작업 표시줄 제외, 표시 상태를 항상 다시 설정한 뒤 `qhud://layer`를 보내고 `qhud ui: layer:pinned` 또는 `qhud ui: layer:below`를 기록합니다. 프레임 가드도 복구 후 같은 재설정을 호출하므로 remap이 사용자의 고정 선택을 조용히 없애지 않습니다. `Reset position`은 모니터를 분리하면 저장된 기하가 사라진 디스플레이를 가리킬 수 있기 때문에 존재합니다(CV-1).

<a id="4-the-poll-loop"></a>

## 4. 관찰 루프

주기는 2초입니다. 각 주기에는 카운터 증가, 15번째마다 창 기하 저장(window-state는 정상 종료에만 저장하지만 위젯은 보통 시그널이나 로그아웃으로 종료됨), 연결된 멀티플렉서가 없고 마지막 시도가 10초 이상 전이면 탐색, 관찰, 페이로드 선택 및 보강, `qhud://report` 전송, 프레임 가드 실행, 대기를 순서대로 수행합니다.

**백엔드 선택**(D-007). qmonster의 `auto`는 herdr 창 _안에만_ 있는 환경 변수로 herdr를 감지하지만 qhud는 보통 모든 창 밖에서 실행됩니다. 따라서 설정이 `auto`이고 `HERDR_ENV`와 `HERDR_SOCKET_PATH`가 모두 없으면 후보 두 개를 만들어 **herdr부터, 그다음 tmux**를 시도합니다. 명시적 `[mux] backend`는 그대로 사용합니다. 후보는 검증 관찰 한 주기를 통과해야 채택되며 보고하는 백엔드 이름은 요청 설정이 아니라 실제로 결정된 소스에서 가져옵니다. 설정은 `~/.qmonster/config/qmonster.toml`에서 읽고 분석 실패를 기록한 뒤 serde 기본값으로 대체합니다.

**멀티플렉서가 없다고 데모를 표시하지 않습니다.** v0.6.0 전에는 mux 없이 시작하면 데모 데이터를 표시했습니다. 이제 창 0개, `source = "local"`, 로컬에서 찾을 수 있는 모든 계정 정보, qhud가 저장한 시각이 명시된 스냅샷으로 구성된 실제 로컬 페이로드를 표시합니다. 누락 사용량은 0으로 채우지 않고 그대로 둡니다. 예시 데이터에는 `--demo`가 필요하며 이 옵션은 실시간 탐색도 완전히 끕니다. mux가 없을 때 사용량을 만들어 내지 않는지, 추가 계정에만 행이 있어도 기본 계정에 접근할 수 있는지를 두 테스트로 보장합니다.

보강 순서는 고정되어 있습니다. 계정 감지, 저장 스냅샷 연결, 계정 연결, 식별 정보만 있는 행 연결, 자리 표시자 연결, 요약의 5시간 최댓값 재계산 순입니다. 저장된 수치가 없는 계정도 표시하여 새로고침 버튼에 접근할 수 있도록 식별 정보 전용 행을 만듭니다.

**소유 계정 검사.** 저장 스냅샷은 계정 ID 또는 이메일이 현재 로그인과 일치할 때만 사용합니다. 이는 이전 로그인의 더 최신 수치가 현재 로그인의 더 오래된 수치를 가리는 문제를 방지하며 v0.6.0에서 해결했습니다. 저장된 Codex 작업 공간의 `active`도 디스크 값을 믿지 않고 현재 계정으로 다시 계산합니다.

**성능 저하 시 동작.** 설정이 없으면 기본값을 사용합니다. 백엔드 하나가 실패하면 다음으로 넘어가고 모두 실패하면 로컬 페이로드로 전환한 뒤 10초마다 재시도합니다. 실행 중 실시간 소스를 잃으면 실제 계정과 저장 사용량을 유지하며 로컬 페이로드로 전환합니다. 이벤트 전송과 기하 저장 실패는 설계상 무시합니다.

<a id="5-paths"></a>

## 5. 경로

v0.6.0에 추가한 `paths.rs`가 모든 위치를 해석하는 유일한 지점이며 빈 환경 변수는 모든 조회에서 미설정으로 취급합니다.

| 대상 | 해석 순서 |
| --- | --- |
| 홈 | Windows: `USERPROFILE`, 그다음 `HOME`. 그 외: `HOME`, 그다음 `USERPROFILE`. |
| qhud 설정 | `QHUD_CONFIG_DIR` 그대로 → `XDG_CONFIG_HOME/qhud`(두 플랫폼) → Windows에서는 기존 `~/.config/qhud`가 있으면 해당 경로, 없으면 `APPDATA/qhud` → 그 외 `~/.config/qhud` |
| Codex 홈 | `CODEX_HOME` → `~/.codex` |
| Claude 설정 디렉터리 | `CLAUDE_CONFIG_DIR` → `~/.claude` |
| Claude 설정 파일 | `CLAUDE_CONFIG_DIR/.claude.json` → `~/.claude.json` |

Windows 홈 우선순위는 의도적입니다. Git Bash 방식의 `HOME`이 네이티브 프로필보다 우선하면 안 됩니다. Windows 설정 디렉터리 순서도 의도적이며 기존 `~/.config/qhud`가 `APPDATA` 이동으로 방치되지 않고 계속 작동하도록 합니다.

코어가 읽는 나머지 환경 변수는 Codex CLI 탐색의 `QHUD_CODEX_BIN`, `LOCALAPPDATA`, `PATH`, Windows 보조 프로세스의 `SystemRoot`, 계정 식별 정보 없는 Claude 응답 진단의 `QHUD_EXTRA_DIAG`입니다.

## 6. 프레임 가드 (Linux 전용, D-017)

관찰 14주기마다, 약 28초마다 위젯은 GdkWindow에서 자체 창의 아래쪽 높이 24픽셀, 최대 너비 420픽셀 띠를 읽어 해시를 계산합니다. 그 위치의 푸터 시계는 매초 다시 그려지므로 바이트 단위로 같은 띠는 컴포지터가 프레임을 표시하지 않는다는 뜻입니다.

복구는 초기화 가능한 2단계 확대 방식입니다. 해시가 바뀌면 진행 중인 복구 상태를 지웁니다. 한 번 정지한 샘플은 창을 숨겼다가 다시 표시하고 계층 상태를 재설정합니다. 두 번째 정지 샘플은 `--respawned`로 프로세스를 재실행합니다. 세 번째에는 이미 재시작 중이므로 아무것도 하지 않습니다. 숨겨진 창에서는 픽셀이 정적인 것이 맞으므로 발동하지 않고 상태를 초기화합니다. 세션의 첫 성공 샘플은 `qhud: frame guard armed (first pixel sample ok)`를 기록합니다. 샘플러 자체가 작동한다는 근거이며 조용히 고장 난 샘플러를 정상 화면으로 오인하지 않게 합니다.

해시는 64비트 FNV-1a이며 한 가지 조정이 있습니다. 0은 “아직 샘플 없음”을 뜻하는 예약값이므로 결과가 0이면 1로 바꿉니다.

Linux가 아닌 빌드에서는 전체 메커니즘을 제외하지만 결정 로직은 모든 플랫폼에서 단위 테스트할 수 있습니다.

<a id="7-window-and-capability-surface"></a>

## 7. 창과 권한 범위

창은 392×520, 장식 없음, 투명, 항상 아래, 작업 표시줄 제외, 모든 작업 공간에 표시, 크기 조절 가능, 최소 320×200입니다. 위치는 선언하지 않으며 window-state 플러그인이 기하를 제공합니다. 프런트엔드에는 번들러가 없어 `withGlobalTauri`로 실행하며 콘텐츠 보안 정책은 자체 소스, 인라인 스타일, data URI 이미지만 허용합니다.

권한은 의도적으로 최소한만 열거합니다. 기본 권한, 커서 위치, webview 확대/축소, 위치 설정, 크기 설정, window-state 플러그인 자체 권한입니다. 위젯의 드래그, 크기 조절, 확대/축소는 컴포지터에 요청하지 않고 네 가지 창 권한으로 수행합니다(D-008).

`bundle.active`는 false입니다. 릴리스는 설치 프로그램이 아니라 압축 파일 안의 원시 바이너리를 제공합니다(D-006).

<a id="8-build-and-release"></a>

## 8. 빌드와 릴리스

`main`에 대한 모든 push와 pull request마다 하나의 CI 워크플로에서 플랫폼 작업 두 개를 실행합니다.

- **Ubuntu 24.04**: `cargo fmt --all --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked --all-targets`, `cargo build --locked --release`.
- **Windows 2022**: Windows 빌드 스크립트를 테스트 모드로 실행한 뒤 `Cargo.toml`과 `Cargo.lock`에 `git diff --exit-code`를 실행하여 기준 의존성 파일이 바이트 단위로 복원됐는지 확인합니다.

릴리스 워크플로는 모든 `v*` 태그에서 실행됩니다. 두 플랫폼을 테스트와 함께 다시 빌드하고 Linux tarball과 Windows ZIP에 각각 SHA-256 파일과 빌드 출처 증명을 붙인 뒤 두 작업이 모두 통과해야 공개합니다. 공개 단계에는 `docs/05-ops/releases/<tag>.md`가 필요합니다. 설명 없이 출시하지 않고 릴리스 노트가 없으면 실패합니다.

**Windows 의존성 패치**는 고정된 qmonster revision이 GUI 프로세스에서 콘솔 창을 띄우고 Unix를 전제한 테스트를 가지고 있어 필요합니다. 패치는 Windows에서는 `CREATE_NO_WINDOW`를 적용하고 다른 곳에서는 아무것도 하지 않는 도우미 하나를 추가해 모든 프로세스 탐색 지점이 사용하게 하며 Unix 전용 테스트를 구분합니다. qhud 트리 밖의 형제 checkout에만 적용하고 임시 `cargo --config` 패치 테이블로 연결한 뒤 제거합니다. 검증한 `Cargo.lock` 한 줄을 제거했다가 `finally` 블록에서 바이트 단위로 복원합니다. 따라서 일반 Linux `cargo build`는 형제 checkout이나 패치 없이 Git에서 qmonster를 가져옵니다.

릴리스 프로필 `strip`, `lto`, `codegen-units = 1`은 workspace 루트 manifest에 있습니다. v0.6.0 전에는 cargo가 무시하는 멤버 manifest에 있었으므로 이전 릴리스는 모두 크기 최적화가 적용되지 않았습니다. v0.5.3은 25.13 MiB였고 v0.6.0은 15.07 MiB입니다. Cargo는 한 달 동안 모든 빌드에서 이 경고를 출력했습니다.

<a id="9-the-payload-contract"></a>

## 9. 페이로드 계약

이벤트 `qhud://report` 하나가 프런트엔드의 모든 정보를 전달합니다. 코어는 qmonster의 풍부한 창 보고서를 작은 표시용 페이로드로 다시 직렬화하므로 webview는 업스트림 타입을 보지 않으며 업스트림 리팩터링의 영향은 파일 하나에 한정됩니다. 이 경계에서 두 변환을 고정합니다. 압박 정도는 0..1 비율로 들어와 정수 백분율로 나가고 초기화 시각은 Unix 초로 나가므로 프런트엔드가 카운트다운 표시를 담당합니다.

Schema 버전은 1이며 모든 릴리스에서 1을 유지했습니다. 필드는 추가만 했고 보통 비어 있는 추가 필드는 null로 보내지 않고 생략합니다.

```
schema, source, backend, generated_at_ms, poll_secs
quotas[]   provider, h5, d7, from_label, session, account?, origin?,
           cache_fetched_at_ms?, scoped[]?, extra?
panes[]    pane_id, label, session, provider, status, status_label,
           elapsed_secs, cli_version, update_hint, model, effort, branch,
           cwd, mem, cost_usd, flags[], gauges{ctx,h5,d7}, conflicts[]
summary    panes, conflicts, max_5h_pct
account_placeholders[]?, workspace_names{}?, workspace_plans{}?,
codex_workspaces[]?, codex_fetched_at_ms?
```

`source`는 `live`, `local`, `demo`입니다. `backend`는 멀티플렉서가 페이로드를 제공하면 `herdr` 또는 `tmux`, 아니면 null입니다. 계기는 `{pct, source, reset_unix, of_tokens}`입니다. `origin`은 `pane`, `cache`, `fetched`이며 프런트엔드가 행을 실시간처럼 표시해도 되는지 판단하는 필드입니다.

`qhud --dump`는 바로 이 페이로드를 보기 좋은 JSON으로 출력합니다. Runbook에서 “수치가 의심스러운가?”에 스크린샷 대신 이 명령으로 답하는 이유입니다.

## 10. 병합 규칙

같은 사실이 최대 세 출처에서 서로 다른 시각의 값으로 도착하며 위젯은 오래된 수치를 현재 값처럼 표시하면 안 되므로 이 규칙이 필요합니다.

**공급자별 집계.** 사용 한도는 창 정보가 아닌 계정 정보(D-011)이므로 같은 공급자의 창은 한 행으로 합치고 기간별 가장 높은 백분율을 사용합니다. 기간 안에서 사용량은 증가만 하므로 각 창의 수치는 하한이며 최댓값이 가장 최신입니다. 5시간 기간에서 채택된 창이 행의 출처도 제공합니다. 5시간 기간이 없을 때만 7일 기간의 창이 출처를 제공합니다.

**만료 스냅샷은 90초 유예 후 제외합니다.** 초기화 시점이 지난 수치는 더 이상 존재하지 않는 기간을 설명합니다. 그렇지 않으면 유휴 창의 어제 88%가 오늘 실제 12%보다 영원히 우선합니다. 초기화 직전 측정값은 새 기간에서도 잠깐은 유효한 정보를 주므로 유예를 둡니다. 한 기간의 모든 수치가 만료되면 기간 전체를 생략합니다. 틀린 값을 보여 주는 것보다 아무것도 보여 주지 않는 편이 낫습니다.

**실시간 창 수치를 덮어쓰지 않습니다.** 저장 스냅샷은 창에 없는 기간을 채우고 스냅샷에만 있는 모델별 기간과 지출을 추가하며 자체 시각을 표시할 수 있지만 창이 보고한 수치를 교체할 수는 없습니다. 빈 곳을 채우는 것은 덮어쓰기가 아닙니다.

**창이 없는 공급자도 행을 받습니다.** 스냅샷에서 행을 만들고 해당 출처를 표시합니다. CLI가 실행되지 않아도 수치를 유지하는 것이 저장 계층의 목적입니다. v0.6.0부터 생성 기준을 낮췄습니다. 모델별 한도만 있거나 추가 지출만 있는 스냅샷도 실제 결과이므로 기본 기간이 없다는 이유로 버리지 않고 행을 만듭니다.

**시각보다 소유 계정이 먼저입니다.** 저장 스냅샷은 현재 로그인 계정에 속할 때만 사용합니다. 시각을 먼저 비교하면 이전 로그인의 최신 값이 현재 로그인의 오래된 값을 가릴 수 있어 v0.6.0에서 수정했습니다. 같은 이유로 저장된 Codex 작업 공간의 활성 여부도 현재 로그인으로 다시 계산합니다.

**한 계정의 수치에 다른 계정의 이름을 붙이지 않습니다.** 추가 계정 행은 자체 식별 정보를 이미 가지고 오므로 식별 정보가 없는 행에만 이를 연결합니다. 활성 Codex 작업 공간은 같은 주간 한도를 시각 차이가 있는 두 사본으로 표시하지 않고 공급자 행에 합칩니다.

## 11. 기간 용어

인터페이스 어디서나 모든 기간을 길이로 표시합니다. 5H, 1D, 7D, 30D이며 프런트엔드의 표 하나에서만 변환합니다. Codex 응답은 “weekly”와 “30d”를 사용하고 운영자는 “weekly”와 “7D”가 다른 것인지 합당하게 질문했습니다. 둘은 같은 7일 이동 기간이므로 하나의 이름을 사용합니다.

Codex 기간 레이블은 primary/secondary 위치가 아니라 **길이**에서 도출합니다. 기준 장비에서 검증했습니다. 2026-07-13 전에는 primary가 5시간, secondary가 주간이었지만 이후 primary가 주간이 되고 secondary는 null이 되었으며 30일 기간이 나타났습니다. Codex 자체와 마찬가지로 qhud도 길이로 이름을 정하며 10% 허용 범위와 미인식 기간의 분 단위 대체 표기를 사용합니다.

모델별 한도는 기본 한도와 기간이 같으므로 두 7D 칩을 구분하는 것은 범위 **이름**뿐입니다. 따라서 공급자 자체 응답 필드에서 페이로드와 표시 레이블까지 범위를 끝까지 전달하며 알 수 없는 한도 종류는 사라지지 않고 툴팁 행으로 표시됩니다.

## 12. 프런트엔드

프레임워크와 번들러가 없습니다. DOM을 제자리에서 수정하므로 2초 새로고침이 CSS 전환을 다시 시작하지 않습니다. 앱 전체는 `withGlobalTauri`를 사용해 Tauri asset 프로토콜로 제공하는 파일 하나입니다.

**렌더링 순서**는 요약, 데모 배지, 전체 새로고침 상태, 사용 한도 영역(구역, 행, Codex 하위 행, 접힌 자리 표시자 행), 페이로드 순서에 따른 키 기반 타일 수정, 푸터입니다. 사용 한도 영역은 예외를 stderr로 전달하는 try/catch 안에서 처리합니다. 과거에는 프런트엔드 예외를 webview 밖에서 볼 수 없어 고장 난 영역을 배포한 적이 있습니다.

**사용량 영역의 행 식별자는 (공급자, 계정, 조직)**이며 코어의 중복 제거 키와 같습니다(D-018). 새 행은 해당 공급자의 마지막 기존 행 뒤에 넣어 두 번째 계정이 구역 제목의 위치를 흐트러뜨리지 않게 합니다. 공급자는 다음 작업을 어디서 할지 결정할 때 운영자가 고르는 기준이고 창 용어와 일치하며 정확히 세 개이므로 계정이 늘어나도 훑어보는 순서가 안정적입니다.

**경과 시간과 출처는 항상 드러납니다.** 경과 시간 표시는 스냅샷 출처 행에만 붙입니다. 실시간 행에는 스냅샷이 모델별 기간만 제공했으므로 배지를 붙이면 보이는 계기가 오래됐다는 오해를 줍니다. 스냅샷의 모델별 칩은 흐리게 표시하고 표식을 붙입니다. 범위별 계기는 캐시에서만 올 수 있어 현재 값처럼 보이면 안 됩니다. 실제는 22%인데 캐시된 5%가 실시간 계기 옆에 표시된 v0.4.0 문제가 이유입니다.

**공급자마다 독립적인 조회 상태 머신이 세 개 있습니다.** 각각 idle → loading → done 또는 error로 전환하고 자체 오류 표시를 가지므로 공급자 하나의 401이 다른 수치를 숨기지 않습니다. 전체 새로고침 버튼은 이들의 합집합을 반영합니다. 실시간 결과는 설정 디렉터리**와** 계정 ID로 행에 연결합니다. v0.6.0에서 계정 ID 조건을 추가하여 새로고침이 잘못된 행에 들어가지 않도록 했습니다.

**선택하면 행 안에서 세부 정보를 확장합니다.** 포인터를 자주 올려놓지 않는 keep-below 창에서는 hover 툴팁을 거의 쓸 수 없으므로 클릭하면 정보를 행으로 옮깁니다. 네트워크는 새로고침 버튼에서만 실행하며 행 선택에서 실행하지 않습니다. 이 webview는 pointerdown은 안정적으로 전달하지만 click을 합성하지 않으므로 모든 조작은 `click`이 아닌 `pointerdown`에 연결합니다(D-009).

**기하는 직접 제어합니다**(D-008). keep-below XWayland 창에서는 컴포지터의 대화형 이동/크기 조절이 불안정하고 창 자체가 움직이면 webview의 화면 좌표가 오래된 값이 됩니다. 따라서 requestAnimationFrame 루프가 Tauri 전역 커서 위치를 읽어 위치나 크기를 직접 설정하고 포인터 이벤트는 루프를 시작하고 중지하기만 합니다. 툴킷이 장식 없는 X11 창의 위치와 크기에 가상의 프레임 높이를 더해 보고하므로 창 자체가 보고하는 값은 의도적으로 쓰지 않습니다. Ctrl+휠은 70–160%로 확대/축소하고 저장하며 위젯은 키보드 포커스를 가져가지 않습니다.

**관찰 가능성은 의도적인 설계입니다.** 하나의 명령을 통해 추적 로그를 stderr로 보내며 렌더링 로직이 무언가 만들었다는 유일한 근거입니다. 영역 구조, 모든 식별 정보 행과 계기 레이블의 실제 텍스트, 실제 pointerdown이 도착한 위치, 선택 변경, 확대/축소, JavaScript 오류를 기록합니다. 개수만으로는 충분하지 않습니다. 잘못된 기간 _이름_은 개수로 찾을 수 없는 오류입니다. 이 모든 것 역시 실제 화면 그리기를 증명하지 못하므로 프레임 가드가 필요합니다.

1초 타이머가 카운트다운을 다시 렌더링하고 8초 동안 페이로드가 오지 않으면 푸터에 오래됨을 표시합니다. 백엔드가 멈추면 그럴듯한 수치를 고정 표시하지 않고 멈췄음을 알립니다(CV-2).

**저장하는 내용과 위치.** 선택 창, 자리 표시자 확장 상태, 확대/축소는 저장 접근이 완전히 거부돼도 처리하는 래퍼 뒤의 브라우저 저장소에 있습니다. 창 기하는 window-state 플러그인에 있으며 관찰 루프가 30초마다 저장합니다.

## 13. 시각 일치 검증 데이터로서의 데모

데모 페이로드는 원래 디자인 목업의 창을 하나씩 재현하므로 동일하게 렌더링하는 것이 시각 일치 테스트입니다(D-005). 창 3개와 충돌 1개를 포함하고 실제 집계로 사용 한도 행을 계산하므로 데모는 별도 경로가 아니라 운영 병합 경로를 실행합니다.

v0.6.0부터는 선택적입니다. `--demo`가 필요하며 실시간 탐색도 끕니다. mux 없는 장비에서도 실제 계정 정보와 운영자의 마지막 새로고침 결과를 시각과 함께 보여 줄 수 있으므로 빈 창 목록은 더 이상 예시 데이터 표시의 이유가 아닙니다.

<a id="14-providers"></a>

## 14. 공급자

공급자 경로는 두 질문으로 결정됩니다. 요청하지 않아도 정보가 도착하는가, 자격 증명은 누가 보유하는가입니다.

| | 수동 관찰, 2초마다 | 명시적 새로고침 | 자격 증명 관리 |
| --- | --- | --- | --- |
| Claude | qmonster를 통한 상태 표시줄; Claude Code 자체 디스크 사용량 캐시; `.claude.json`의 계정 정보 | 로그인한 설정 디렉터리마다 `GET https://api.anthropic.com/api/oauth/usage` 한 번 | qhud가 HTTP 요청에 기존 액세스 토큰을 사용 |
| Codex | 활성 로그인의 창 상태 표시줄; `auth.json`의 계정 정보 | 저장된 자격 증명마다 `wham/accounts/check` 후 `wham/usage`; 활성 로그인 실패 시 짧게 실행한 `codex app-server` 자식이 stdio로 응답 | HTTP 경로는 qhud가 액세스 토큰을 읽고 대체 경로는 CLI가 모두 관리 |
| agy | 창이 있으면 상태 표시줄; `google_accounts.json`의 계정 정보 | 실행 중인 agy 프로세스에 loopback Connect RPC; 토큰과 CSRF 없음 | agy 자체 — qhud는 자격 증명을 전혀 읽지 않음 |

모든 공급자에 세 규칙을 적용합니다(D-014, D-016).

- **타이머로 실행하지 않습니다.** 관찰 루프는 로컬 파일과 멀티플렉서를 읽습니다. 장비 밖으로 나가는 모든 바이트는 운영자가 요청했기 때문입니다.
- **Refresh grant를 실행하지 않습니다.** Codex refresh token은 일회용이며 회전합니다. 회전 결과를 저장하지 못하면 운영자의 로그인이 깨집니다. Claude Code 자체 갱신과 경합해도 로그인이 깨지므로 Claude 토큰과도 경합하지 않습니다.
- **위임을 우선합니다.** 공급자 자체 프로세스가 응답할 수 있으면 맡깁니다. 그러면 토큰 회전과 키링 자격 증명은 공급자가 관리합니다.

**Claude.** 호출마다 최신 자격 증명에서 액세스 토큰만 읽고 옆의 refresh token은 사용하지 않습니다. User agent는 필수 조건입니다. 실제 `claude-code/<version>`이 없으면 이 endpoint는 재시도 정보 없는 429를 반환합니다. 응답에는 계정 UUID와 이메일이 있어 절대로 기록하지 않으므로 계정 정보는 응답 대신 설정 디렉터리 자체 파일에서 가져옵니다. 유일한 예외는 형식 변경 진단용 환경 변수로 제한된, 식별 정보 없는 하위 객체 두 개의 출력입니다. 새로고침 한 번에 기본 계정과 등록된 모든 추가 디렉터리를 조회하고 각 저장 키에 기록합니다. 부분 실패는 부분 실패로 유지하여 만료된 추가 계정이 기본 계정 수치를 숨기지 않게 합니다. 거부된 응답은 serde의 필드/타입 메시지를 보고하며 구조상 식별 정보가 없습니다. 필드 이름 없는 “did not parse”는 진단에 이틀을 쓰게 하기 때문입니다(D-019).

**Codex.** 등록된 모든 홈의 `auth.json`과 보관된 형제 파일을 읽고 활성 파일을 먼저 정렬하여 우선하도록 계정 ID로 중복 제거합니다. 서버가 토큰 하나를 다른 작업 공간으로 재지정하지 않으므로 자격 증명마다 자체 작업 공간을 읽습니다. 요청 계정과 다른 계정을 설명하는 응답은 잘못 표시하지 않고 제외한 뒤 불일치를 기록합니다. 기간 이름은 primary/secondary 위치가 아니라 **길이**에서 가져옵니다. 활성 로그인의 HTTP 경로가 실패하면 읽기 전용, on-request 승인으로 `codex app-server` 자식을 실행하고 stdio로 3줄 JSON-RPC 초기 교환을 전달합니다. EOF에서 서버가 응답 전에 종료할 수도 있으므로 stdin은 의도적으로 열어 둡니다. 25초 후 종료합니다. v0.6.0부터 한도별 맵은 누락/null/빈 값이어도 되고 최상위 한도도 null일 수 있습니다. 하나만 있어도 충분하며 기본 한도는 정확히 한 번만 사용해 주간 기간을 중복 표시하지 않고 최상위 null이 실제 모델별 수치를 가리지 않게 합니다.

**agy.** 실행 중인 agy는 토큰과 CSRF 없이 한도 요약에 응답하는 loopback listener를 엽니다. 포트는 운영체제 자체 테이블에서 찾습니다. Linux에서는 agy 프로세스 소켓 inode와 `/proc/net/tcp`의 loopback listener를 결합하고 Windows에서는 포트 번호만 반환하는 숨겨진 PowerShell 쿼리를 사용합니다. 후보를 순서대로 시도하며 HTTPS listener는 일반 HTTP를 거부하므로 스스로 제외됩니다. 응답은 기본값을 생략하는 proto3 JSON입니다. 남은 비율이 없으면 “알 수 없으니 정상”이 아니라 남은 것이 없다는 뜻입니다. 새로고침 시작 시점의 계정 정보를 결과에 붙여 이후 로그인이 저장 스냅샷의 이름을 바꾸지 못하게 합니다.

## 15. 분석과 스냅샷 구조

기본 기간 두 개, 범위별 기간 목록, 선택적 지출을 가진 스냅샷 하나가 모든 공급자의 수치를 전달하므로 렌더러에 두 번째 경로가 필요 없습니다. Claude 디스크 캐시와 qhud 자체 새로고침 결과는 직접 이 구조로 분석하고 Codex 작업 공간과 agy 한도는 여기에 매핑합니다.

세 가지 분석 규칙이 필요합니다.

- **백분율 누락은 “그 한도가 없음”이며 0이 아닙니다.** 해당 기간이 없는 플랜은 null을 보고하며 이를 0%로 표시하면 실제로는 그런 한도가 없는데도 사용량이 없다고 주장하게 됩니다. 종류나 백분율이 없는 한도는 0으로 채우지 않고 제외하며 현재 응답에 없는 모델도 0%로 표시하지 않고 화면에서 제거합니다.
- **정수 의미의 숫자는 의미대로 읽습니다**(D-019). 정수값인 실수는 해당 정수입니다. 소수부가 있는 실수는 단위가 모호하므로 제외합니다. 단위를 추정하면 50달러를 50센트로 보여 줄 수 있기 때문입니다. 어느 경우에도 주변 응답 전체를 실패시켜서는 안 됩니다.
- **금액은 실수형으로 왕복 변환하지 않습니다.** 지출은 최소 화폐 단위, 통화, 지수입니다. 한 객체만 limit-reached 플래그를 제공하므로 두 응답 객체 중 하나만 선택하지 않고 필드마다 더 풍부한 값을 사용합니다.

Claude Code 자체 캐시와 qhud 마지막 조회가 모두 있으면 최신 것을 사용하고 시각이 같으면 최소한 동등하게 완전한 qhud 조회를 우선합니다. 어느 경우든 행에 출처와 시각을 표시합니다.

## 16. 계정 식별

CLI가 이미 관리하는 로컬 파일에서 계정 필드를 선택하며, 관찰을 위해 공급자 네트워크 요청을 보내거나 토큰을 사용하지 않습니다. Claude 설정 파일, Codex `auth.json`의 계정 ID, agy의 활성 Google 계정이 대상입니다. 로그아웃한 공급자는 행을 제공하지 않습니다. 읽을 수 없거나 잘못된 파일은 단순히 계정이 없는 것으로 봅니다. 이는 보강 정보이며 관찰 주기를 실패시켜서는 안 됩니다.

**행 식별자는 (계정, 조직) 쌍입니다**(D-018). 하나의 claude.ai 로그인이 팀 좌석과 개인 조직에 속할 수 있고 각각 별도 한도가 있으므로 같은 조직의 같은 계정만 중복입니다. 프런트엔드도 같은 키를 쓰며 새로고침 결과는 설정 디렉터리**와** 계정 ID로 행에 연결합니다. 계정만 비교하면 하나의 로그인에 속한 두 행 모두에 한 조직의 수치를 넣게 됩니다.

표시 이름은 운영자가 제공하며 저장소 밖의 registry 파일에서 덧붙입니다. 공급자 내부 용어는 운영자가 보는 이름이 아니므로 응답 플랜 문자열로 “수정”하지 않습니다.

## 17. Registry와 자리 표시자

운영자가 소유한 파일 하나에 표시 레이블, 작업 공간 이름과 플랜, 과거 연결 계정 목록, 제거 항목, 다중 계정에 필요한 추가 Claude 설정 디렉터리 및 Codex 홈을 저장합니다(D-015).

자리 표시자 규칙은 우선순위대로 세 가지입니다.

1. 유효한 자격 증명은 항상 표시합니다. 현재 사실을 숨기지 않습니다.
2. 알려진 계정에 유효한 자격 증명이 없으면 복구 방법을 담은 자리 표시자로 표시합니다. 해당 한도는 계속 진행되므로 숨기면 정보를 누락하게 됩니다.
3. 운영자가 명시적으로 제거한 계정은 자리 표시자로 나타나지 않습니다. 제거는 활성 계정을 숨기지 **않습니다**. 그 경우에는 로그아웃해야 합니다. 사용 중인 항목을 조용히 숨기는 편이 더 큰 오류입니다.

qhud는 해당 파일에서 제거 목록 키 하나만 씁니다. 직접 관리하는 키를 보존하도록 타입 구조체가 아닌 일반 JSON으로 편집합니다. 잘못된 내용은 빈 registry로 읽습니다. 관찰 주기를 실패시킬 만큼 필수적인 정보가 아니기 때문입니다.

<a id="18-persistence"></a>

## 18. 저장

파일 두 개 모두 계정 ID를 포함하므로 이 저장소 밖에 있습니다. 관찰 루프가 매 주기 다시 읽고, 과거 상태 표시줄 보조 파일이 제자리 잘라 쓰기로 불완전한 읽기를 만들었으므로 모두 임시 파일 후 이름 변경 방식으로 씁니다.

- `accounts.json` — 앞서 설명한 운영자의 registry입니다.
- `fetched-usage.json` — 명시적 새로고침 결과입니다. 기본 Claude 계정, 설정 디렉터리로 구분한 추가 Claude 계정, 조회 시각이 있는 Codex 작업 공간, agy를 저장합니다. 삭제해도 다음 새로고침이 다시 만듭니다.

잘못된 내용, 오래된 schema, 누락 파일은 모두 빈 저장소로 읽습니다. 새 빌드가 쓴 저장소가 이전 빌드를 깨뜨리지 않도록 알 수 없는 필드는 무시합니다.

**동시 새로고침은 서로의 결과를 지우지 못합니다.** 세 공급자의 새로고침은 동시에 실행됩니다. v0.6.0 전에는 각각 독립적으로 읽고 수정하고 저장하여 동시에 끝난 두 작업이 모두 병합 전 상태를 기반으로 쓸 수 있었습니다. 이제 읽기, 병합, 원자적 교체 전체에 프로세스 전역 잠금을 유지합니다. 회귀 테스트는 barrier로 동기화한 쓰기 작업 8개를 실행하고 모두 남는지 확인합니다.

qhud는 qmonster 자체 디렉터리에 아무것도 쓰지 않습니다. TUI가 해당 상태를 관리하며 두 번째 쓰기 주체는 경합을 일으킵니다(D-004).

<a id="19-invariants"></a>

## 19. 불변 조건

아래 규칙은 현장 장애를 겪고 배운 것입니다. 각각 코드로 강제하고 테스트로 확인합니다.

- **오래된 수치가 현재 값처럼 보이면 안 됩니다.** 스냅샷 출처 행에는 경과 시간을, 캐시 모델별 칩에는 흐린 표시와 표식을 붙이고 만료 기간은 생략합니다. 실제는 22%인데 한 모델의 캐시 5%가 실시간 계기 옆에 나타난 문제가 배경입니다.
- **오류가 없다는 사실은 실제로 그려졌다는 증거가 아닙니다.** 추적 로그는 로직을 증명할 뿐 픽셀을 증명하지 못합니다. 이 구분을 놓쳐 3일을 잃었기 때문에 픽셀 가드가 존재합니다(D-010, D-017).
- **하나의 사실에는 하나의 이름, 하나의 이름에는 하나의 사실**(D-011). 기간은 어디서나 길이로 이름 붙이고 범위 이름을 끝까지 전달하며 기간이 같아도 모델별 한도를 기본 한도에 합치지 않습니다.
- **누락은 누락으로 유지합니다.** 0 채우기, 가상 한도 생성, 공급자가 언급하지 않은 모델의 0% 생성은 없습니다.
- **부분 실패는 부분 실패로 유지합니다.** 한 공급자의 401이나 만료된 추가 계정이 다른 수치를 숨기지 않습니다.
- **관찰 루프는 수동적입니다.** 로컬 파일과 멀티플렉서만 읽습니다. 네트워크와 RPC는 명시적 버튼과 대응 CLI 명령 뒤에 있습니다.
- **시각보다 소유 계정이 먼저입니다.** 스냅샷은 소유 계정에만 사용합니다.
- **Refresh grant는 절대 실행하지 않습니다.** qhud는 OAuth refresh grant를 실행하지 않습니다. 관찰에서는 공급자 토큰을 사용하지 않고 계정 필드를 선택합니다.
