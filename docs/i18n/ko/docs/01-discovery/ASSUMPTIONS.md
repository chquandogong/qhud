# 가정 — qhud

> 상태: 지속 갱신 · 날짜: 2026-09-07 · 담당: chquandogong
> v0.6.1에 맞춰 전면 개정했습니다. 이전 목록은 v0.4.0 시점의 것으로, 오래된 의존성 revision, v0.6.0에서 더 이상 성립하지 않는 단일 플랫폼 전제, qhud 자체 상태에는 처음부터 맞지 않았던 “아무것도 저장하지 않음” 주장, 한 달 뒤에는 해석할 수 없는 상대 날짜(“오늘 검증”)가 포함되어 있었습니다. 여기서는 항상 절대 날짜를 사용합니다.

| ID | 가정 | 상태 | 근거 / 재검토 조건 |
| --- | --- | --- | --- |
| A1 | 기본 **터미널 모니터링** 대상은 GNOME Wayland 워크스테이션 한 대입니다. Windows x64는 창 관찰이 없는 **계정 사용량** 지원 대상입니다. 다른 데스크톱은 최선의 호환성을 제공하며 macOS는 제외합니다. | 채택, 2026-09-07 수정 | v0.6.0에서 별도 CI 작업, 릴리스 파일, 운영 가이드를 갖춘 Windows 네이티브 대상을 추가했습니다. KDE 또는 wlroots 사용자가 나타나 layer-shell 경로를 추가할 가치가 생기면 재검토합니다. |
| A2 | Mutter는 XWayland 창의 `_NET_WM_STATE_BELOW`와 `_STICKY`를 따릅니다. | 2026-09-07 검증 | 공개 v0.6.0 Linux 배포 파일로 재검증했습니다. `_NET_WM_STATE`에 BELOW, STICKY, SKIP_TASKBAR, SKIP_PAGER가 있고 `_NET_WM_DESKTOP`은 `0xFFFFFFFF`였습니다. 최초 근거는 실현 가능성 실험입니다. Linux에만 해당합니다. |
| A3 | 두 모니터가 scale 1로 실행되어 XWayland 소수 배율의 흐림 문제가 적용되지 않습니다. | 2026-09-07 검증 | eDP-1 2560×1600과 HDMI-1 3840×2160 모두 scale 1입니다. 소수 배율을 활성화하면 재검토합니다. GNOME 46은 XWayland를 흐리게 표시하며 GNOME 47+는 이를 개선합니다(R3). |
| A4 | qmonster TUI가 자체 디렉터리 아래의 모든 것을 관리합니다. 두 번째 쓰기 주체는 데이터베이스와 경합을 일으킵니다. | 설계에 따라 채택 | `NoopSink`와 `SilentNotify`(D-004). qhud는 registry, 조회 저장소, 창 기하 같은 **자체** 상태를 별도 위치의 qhud 설정 디렉터리에 임시 파일 후 이름 변경 방식으로 저장합니다. 불변 조건은 “아무것도 쓰지 않음”이 아니라 “`~/.qmonster` 아래에 쓰지 않음”입니다. |
| A5 | `src-tauri/Cargo.toml`에 고정한 revision의 qmonster 라이브러리 API가 계약이며, 업스트림은 변경될 수 있습니다. | 고정 | Revision을 본문에 다시 적지 않습니다. 이전 행에 기재한 revision은 한 달 전에 대체된 상태였습니다. 의도적으로 갱신하고 `view.rs`의 계약 테스트를 다시 실행합니다. Windows는 같은 revision에 저장소 내 패치를 더하며 해당 플랫폼의 Cargo 명령에만 적용합니다(D-020). |
| A6 | 알림은 TUI와 공급자가 담당합니다. 위젯까지 알리면 중복 알림이 발생합니다. | 채택 | `SilentNotify` |
| A7 | 데모 페이로드는 시각 일치 검증 데이터로 사용할 만큼 디자인 목업을 충실히 반영합니다. | 채택, 2026-09-07 범위 축소 | 검증 데이터로는 여전히 유효하며 실제 집계 로직도 실행합니다. 원래 가정의 다른 절반인 “멀티플렉서에 연결할 수 없을 때 데모 데이터를 대체 표시해도 된다”는 v0.6.0에서 **철회**했습니다. 이제 mux 없이 시작하면 실제 계정을 표시하고 데모에는 `--demo`가 필요합니다(D-005). |
| A8 | X11 백엔드는 `visibleOnAllWorkspaces`와 `alwaysOnBottom`을 따릅니다. | 2026-09-07 검증 | 창이 실제로 생성된 뒤와 계층을 전환할 때마다 코드에서 다시 설정하고 `xprop`으로 확인했습니다. Windows에 대해서는 동등한 주장을 하지 않으며 이를 만들어 내서도 안 됩니다. |
| A9 | 푸터 시계가 매초 다시 그려지므로 28초 간격의 픽셀 띠가 바이트 단위로 같으면 컴포지터가 화면을 갱신하지 않는 것입니다. | 핵심 전제, 가정 자체는 미검증 | 프레임 가드의 전체 전제입니다(D-017). 정당한 이유로 푸터가 멈추면 가드가 오탐하여 정상 창을 숨겼다 표시합니다. 푸터 내용이 조건부로 바뀌면 재검토합니다. |
| A10 | 숨겼다가 표시하면 정지한 창의 화면 갱신이 재개됩니다. | 2026-08-13 실제 정지 상태에서 1회 검증 | 실제로 정지한 인스턴스에서 입증했고 이후 현장의 정지 28회가 이 단계에서 복구되었습니다. **두 번째** 단계인 재실행은 현장에서 발동한 적이 없으므로 단위 테스트로만 검증되어 있습니다. |
| A11 | 공급자 CLI는 문서에 기재한 경로에 계정 식별 정보를 평문으로 저장합니다. | 채택 | Claude 설정 파일, Codex `auth.json`의 계정 ID, agy의 활성 Google 계정(D-013). 이제 경로는 환경 변수로 바꿀 수 있으므로 이 가정은 위치가 아니라 필드 이름에 관한 것입니다. 공급자가 계정 식별 정보를 키링으로 옮기면 재검토합니다. agy의 실시간 토큰은 이미 키링에 있고, 이것이 agy 다중 계정을 구현하지 않은 이유입니다. |
| A12 | 활성 Codex 로그인의 작업 공간 한도는 해당 창의 상태 표시줄이 보고하는 한도와 같습니다. | 채택 | 같은 주간 한도를 시각 차이가 있는 두 사본으로 표시하지 않고 작업 공간을 계정 행에 합치는 이유입니다(v0.5.0). Codex가 창 한도와 계정 한도를 구분해 보고하면 재검토합니다. |
| A13 | 모든 Windows 대상에 Edge WebView2 Runtime이 있습니다. | 필수 조건, qhud가 확인하지 않음 | 사전 요구 사항으로 명시합니다. 위젯이 이를 감지하거나 설치하지 않습니다(R15). Windows 사용자가 아무 메시지 없이 시작되지 않는다고 보고하면 재검토합니다. |
| A14 | 공급자의 응답 형식은 **안정적이지 않으며**, 정수형 필드도 다른 형식으로 도착할 수 있습니다. | 실제 장애 후 채택, 2026-09-01 | 반대 가정으로 새로고침이 이틀간 멈췄기 때문에 기록하는 역방향 가정입니다. 정수 의미를 가진 새 필드는 모두 유연한 읽기 함수를 거쳐야 하고, 선택적 필드 하나가 응답 전체를 실패시켜서는 안 됩니다(D-019, R14). |
