## [0.7.1] — 2026-09-11

<!-- qhud:anchor -->
<a id="intel-gpus-on-linux"></a>

### Linux Intel GPU 측정

- Linux에서 Intel GPU를 측정합니다. i915·xe 드라이버는 busy 백분율을 제공하지 않으므로,
  GT별 유휴 잔류 카운터를 읽어 표본 구간에 대한 여집합을 사용률로 보고하며, Windows 엔진
  카운터와 같은 규칙으로 가장 바쁜 GT를 취합니다. 카드의 첫 측정은 빈 구간이고, 카운터가
  초기화되면 100%를 지어내지 않고 빈 구간을 유지합니다. VRAM은 표시하지 않습니다. 이
  GPU들은 MEM이 이미 보고하는 공유 시스템 메모리를 사용합니다.

v0.7.0이 추가한 GPU 칸을 Linux의 어떤 측정원도 Intel 그래픽에서 채우지 못했습니다.
이미 busy 백분율을 제공하는 장치는 그대로입니다. amdgpu는 sysfs 값을, NVIDIA는
NVML을 계속 사용합니다. Ubuntu 24.04에서 Intel Arc(Meteor Lake, i915)로 검증했으며,
같은 구간을 독립적으로 계산한 rc6 잔류 값과 정확히 일치했습니다.
[0.7.1 릴리스 노트](docs/05-ops/releases/v0.7.1.md)를 참조하세요.

## [0.7.0] — 2026-09-11

<!-- qhud:anchor -->
<a id="system-strip-and-about"></a>

### 시스템 그래프와 정보

- CPU·메모리·지원되는 GPU·물리 디스크 입출력·네트워크 속도를 표시하는 작은
  하단 그래프를 추가했습니다. 2초마다 측정하고 최근 최대 60초를 보관하며,
  항목 버튼으로 기본 영역을 크게 늘리지 않고 상세 정보를 확인합니다.
- CPU·메모리·GPU는 백분율 고정 축, 디스크·네트워크는 속도에 맞춘 축을 사용합니다.
  측정 불가·준비 중 값은 빈 구간으로, 정상 유휴 상태는 0으로 표시합니다.
  긴 측정 공백이나 창 표시 상태 변경 후에는 속도 기준값과 기록을 초기화합니다.
- 숨김·최소화 중에는 시스템 측정을 멈춥니다. 기록은 메모리에 보관하며
  로컬 네이티브 측정으로 프로세스 스캔·모니터링 자식 프로세스·원격 측정을 피합니다.
- 사용 가능한 Windows WDDM GPU Engine 카운터와 Linux AMD sysfs / NVIDIA NVML을
  지원합니다. 측정 세션마다 선택한 어댑터 하나를 유지하며 VRAM 상세는 조건부로
  현재 Linux에서만 제공합니다.
- 독립적으로 두 표본을 측정하는 `--system-dump` 진단과 명시적 데모 모드용
  합성 시스템 지표를 추가했습니다.
- 왼쪽 위 qhud 이름을 통해 About을 열어 실행 중인 빌드 버전,
  제작자 Chenghao Quan (chquandogong),
  [제작자 홈페이지](https://chquandogong.github.io/CHENGHAO-QUAN/)와 저장소를 확인합니다.

디스크 속도는 물리 장치 전체를 합산합니다. 용량 상세는 중복을 제거한 로컬 볼륨이며
30초마다 갱신합니다. 네트워크 속도는 루프백을 제외하지만 VPN·가상·물리 인터페이스에서
같은 트래픽이 중복될 수 있습니다. GPU 카운터 미지원은 GPU가 없다는 뜻이 아닙니다.
지원 범위는 [0.7.0 릴리스 노트](docs/05-ops/releases/v0.7.0.md)를 참조하세요.

### 수정

- 현재 Codex 홈의 로컬 `auth.json` ID 토큰에 있는 이메일을 자동 표시하며 `CODEX_HOME` 설정을 따릅니다. 로그인 정보에 이메일이 있으면 새 컴퓨터에서 계정 레이블을 수동으로 연결할 필요가 없습니다.

## [0.6.1] — 2026-09-07

문서 및 검증 릴리스다. 동작 변경은 없다. 소스 수정은 오래된 주석뿐이며 바이너리는 v0.6.0과 동일하게 동작한다.

<a id="changed"></a>

### 변경

- **SPEC과 ARCHITECTURE를 부분 수정하지 않고 v0.6.0 소스 기준으로 처음부터 다시 작성했다.** 이전 SPEC은 v0.5.0에 머물러 있었고 이전 ARCHITECTURE는 v0.4.0 문서였다. 두 문서에는 모듈 네 개(`agy_usage.rs`, `fetched_store.rs`, `frame_guard.rs`, `paths.rs`), 두 플랫폼의 경로 처리, 프레임 가드, 양 플랫폼 릴리스, 코드에서 다루는 명령행 플래그 열한 개 중 다섯 개와 환경 변수 스무 개 중 열여덟 개가 누락되어 있었다. 표의 모듈별 줄 수도 전부 틀렸다. 이제 요구사항은 출시한 모든 릴리스를 다룬다. FR-1 … FR-24는 다른 문서가 인용하는 번호를 유지하고, FR-25 … FR-34는 v0.5.1 → v0.6.0 작업에 지금까지 없던 명세 행을 부여한다(행 내부 선택, 프레임 가드, (계정, 조직) 식별자, 관대한 전송 숫자 처리, Windows 위젯, 실제 계정 대체 경로, 스크롤과 정확한 초기화 시각, 모델 전용 스냅샷, 동시 새로고침, 스냅샷 소유권). 모듈 표에서 줄 수를 제거했다. 모든 릴리스에서 틀렸기 때문이다. 두 주장도 폐기했다. Windows는 더 이상 “범위 밖”이 아니며, “웹뷰 밖에서 픽셀을 검증할 수 없다”는 말은 D-017이 입증한 사실의 정반대인데도 ARCHITECTURE와 README에서 계속 반복되고 있었다.
- **RISK_REGISTER를 다시 작성했다.** v0.4.0부터 그대로였으며 전적으로 Linux를 전제로 했고 현장의 지배적인 장애를 다루는 행도 없었다. 이제 상태는 명시적 열이고, 현실화된 위험에는 발생 날짜가 있다. 새 행 여섯 개를 추가했다. 디스플레이 절전 후 프레임 정지, 공급자 전송 형식 변화(세 번 현실화), WebView2 런타임 요구사항, Windows 의존성 패치와 lockfile 처리, 오래된 값의 현재 값 표시, 다른 계정 이름으로 표시되는 한 계정의 숫자다.
- **ASSUMPTIONS를 다시 작성했다.** 고정 리비전 가정에는 한 달 전에 대체된 리비전이 적혀 있었으며, 이제 특정 리비전을 아예 명시하지 않는다. 단일 플랫폼 전제, “절대 영속화하지 않는다”는 주장, 상대적인 “오늘 검증” 날짜를 바로잡았다. 가정 여섯 개를 추가했다. 푸터 시계가 매초 다시 그려진다는 프레임 가드의 전제와, 공급자 전송 형식은 안정적이지 *않다*는 역방향 가정도 포함한다.
- `view.rs`, `main.rs`, `demo.rs`, `usage_cache.rs`, `codex_usage.rs`의 오래된 주석을 수정했다. 페이로드 `source`에 v0.6.0부터 `"local"`이 추가되었지만 문서 주석은 값 두 개만 나열했다. 진단 플래그 하나에는 이웃 플래그 설명이 붙어 있었다. 데모 모듈은 여전히 mux가 없을 때의 대체 경로라고 주장했다.

### 기록

- **공개된 v0.6.0 빌드로 Ubuntu를 재검증**하여, Windows 호스트에서 출시하며 v0.6.0에 기록했던 검증 공백을 해소했다. Linux 릴리스 자산의 체크섬을 확인하고 기준 컴퓨터에 설치·실행했다. `_NET_WM_DESKTOP`이 `0xFFFFFFFF`인 상태에서 모든 데스크톱 계층 상태를 확인했다. 3초 간격으로 얻은 두 `xwd` 해시가 달라 창이 그려짐을 확인했다. 프레임 가드 활성화, 창 분할 여덟 개의 herdr 관찰, 세 공급자 모두의 새로고침 응답도 확인했다. 같은 트리로 로컬 fmt, 경고를 오류로 취급한 clippy, 98/98 테스트, 릴리스 빌드를 통과했다. 날짜별 행은 TEST_PLAN에 있다.
- **프레임 가드의 현장 집계는 기록보다 다섯 배 컸다.** 저널 수집 기간 2026-08-26 → 09-07: 멈춤 28건, 첫 단계 복구 28건, 재실행 0건, 운영자가 알아차린 문제 0건. 멈춤은 디스플레이 절전 뒤 수분 간격으로 몰린다. 이전 수치는 stderr가 저널에 도달하지 않은 터미널 연결 인스턴스에서 얻었으므로 재산출할 수 없다.
- **v0.6.0에서 Linux 바이너리가 25.13 MiB에서 15.07 MiB로 줄었다.** 이유를 기록할 가치가 있다. `[profile.release]`가 cargo가 무시하는 멤버 매니페스트에 있었기 때문에 `strip`, `lto`, `codegen-units = 1`은 어떤 릴리스에도 적용된 적이 없었다. v0.5.3은 조용히 D-014의 25 MB 예산을 초과했다. Cargo는 한 달 동안 매 빌드마다 그 경고를 출력했다. 로컬 빌드가 아니라 릴리스 자산을 측정해야 한다.
- v0.5.3의 전송 형식 변화 수정은 효과를 유지했다. 2026-09-04 이후 모든 Claude 새로고침이 성공했다. `~/claude-personal`은 여전히 401을 반환한다. 토큰이 2026-08-17에 만료되었으며 운영자의 로그인으로만 해결된다.

### 태그 생성 후 정정

- **v0.6.1 태그 생성 당시 위 집계가 틀렸다.** 해당 항목은 이전 ARCHITECTURE에서 “CLI 플래그 열한 개 중 여덟 개와 환경 변수 아홉 개”가 빠졌다고 주장했다. 소스에서 세어 보니 열한 개 중 여섯 플래그와 스무 개 중 두 환경 변수를 적고 있었으므로, 누락은 다섯 개와 열여덟 개였다. 이번 릴리스의 `docs:` 커밋 메시지도 SPEC의 새 길이를 실제 263줄 대신 322줄로 적었다. 공개 후 `main`에서 정정했다. 공개된 v0.6.1 아카이브에는 원래 문구가 남아 있고 태그 위치도 유지했다. 조용히 수정하지 않고 기록한다. 잘못된 집계 자체가 주제인 릴리스에서 집계를 잘못한 일은 바로 이 프로젝트가 기록해 두는 종류의 일이기 때문이다.

<!-- qhud:anchor -->
<a id="fixed"></a>

### 수정

- Codex app-server 대체 경로가 지원되는 `on-request` 승인 옵션을 사용한다. 레거시 또는 모델별 한도 필드가 누락되거나 null이어도 다른 유효한 값을 숨기지 않는다. 주 풀은 중복 없이 한 번 유지한다.
- Spark 5H/7D를 포함한 모델 전용 스냅샷이 재시작 후에도 백분율과 개별 초기화 시간을 유지한다.
- 공급자 동시 새로고침이 서로의 저장 결과를 보존한다. 로그인 변경 후 캐시 사용량은 현재 계정과 일치하는지 확인한 뒤 표시한다.

<!-- qhud:anchor -->
<a id="compatibility"></a>

### 호환성

- Linux는 고정 Git 의존성, GTK 프레임 가드, X11 동작, tmux/herdr 관찰을 유지한다. Windows 의존성 패치는 Windows 빌드 명령으로 한정한다. 일반 Linux 소스 빌드에는 형제 체크아웃이 필요 없다.
- 두 플랫폼 모두 멀티플렉서 없이 시작하면 실제 로컬 계정 스냅샷과 창 분할 0개를 표시한다. 예시 데이터에는 `--demo`가 필요하다.
- `QHUD_CONFIG_DIR`, `XDG_CONFIG_HOME`, `CODEX_HOME`, `CLAUDE_CONFIG_DIR`를 존중한다. 기존 Linux 기본 경로도 계속 동작한다. 계정 식별 정보가 없는 이전 Antigravity 스냅샷은 명시적 새로고침 한 번이 필요하다.
- 네이티브 Windows 터미널 창 분할/프로세스 귀속은 구현하지 않았다. 공급자의 현재 응답에 없는 모델을 0% 한도로 만들어 표시하지 않는다.

GNOME의 keep-below XWayland 창에서는 컴포지터 측 대화형 이동/크기 변경(드래그 영역, `startResizeDragging`)이 동작하지 않는다. tao의 보이지 않는 테두리 없는 크기 변경 안쪽 영역이 테두리 ~10px 이내의 모든 포인터 입력을 삼켰고, 크기 변경 손잡이가 그 안에 있었다. 창이 움직이는 동안 WebKitGTK `screenX/Y`가 오래된 값이 된다. tao `outerPosition/outerSize`는 가상의 ~37px 프레임을 보고한다. 이제 위치·크기 상호작용은 DOM에서 얻은 잡기 치수와 전역 `cursorPosition()`의 rAF 루프로 전부 자체 구동한다. 두 모니터 모두 픽셀 단위로 정확함을 검증했다.
- **재빌드 시 오래된 UI 자산**: `tauri::generate_context!`가 `../ui`를 cargo 변경 추적에 등록하지 않는다. 이제 `build.rs`가 `cargo:rerun-if-changed=../ui`를 출력한다.
- **로그아웃/강제 종료 시 창 위치·크기 소실**: window-state 플러그인은 정상 종료 때만 영속화한다. 이제 폴링 루프에서 30 s마다 위치·크기를 체크포인트로 기록한다.

<a id="changed-6"></a>

### 변경

- tao 가장자리 영역을 벗어나는 내부 입력 구역으로 크기 변경 손잡이를 확대했다. 권한은 `cursor-position`, `set-position`, `set-size`, `window-state:default`만 남겼다.
