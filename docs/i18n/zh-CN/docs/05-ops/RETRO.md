## 周期 3 — v0.4.0 → v0.5.0（2026-08-07 → 10）

<!-- qhud:anchor -->
<a id="what-worked-1"></a>

### 有效做法

- **将操作者产品表述直接变成计划**：“一眼看到每个账户和工作区，显式刷新，不再打开网页”，直接成为本周期六个单元：额外支出、持久化、全部刷新、D-015 多账户、agy RPC、codex app-server，没有推测性功能。
- **委托获取路径（D-016）**：由供应商进程回答，codex app-server 和 agy 环回解决原始 HTTP 无法解决的令牌轮换与钥匙串凭据问题，qhud 不接触认证。
- **每个解析器和合并规则先写测试**，保证多来源合并可信：attach_accounts 覆盖错误在任何渲染前就被 RED 测试发现。

<!-- qhud:anchor -->
<a id="what-to-fix-next-cycle-2"></a>

### 下个周期要改进

- **每次接入新数据源都会再违反 D-011。** 一天三次，均由操作者发现，形态相同：两个值一个名称，两个“weekly”标签；一个事实两个名称，weekly 与 7D；一个事实两行，账户行与其当前工作区。纠正措施部分已执行：每个新窗口/池/行必须端到端携带 scope **名称**，显示术语固定为 5H/1D/7D/30D，`labels(...)` 现输出实际仪表标签，让下一次违规可从 stderr 看见，无需等待操作者目测。
- **app.js 被写入 NUL 字节**，grep 将其视为二进制并静默无匹配，而 Node 仍能解析。纠正措施：生成键的分隔符用普通空格；“grep 突然找不到任何内容”现在被识别为文件损坏症状，而非字符串不存在。
- **`cargo clippy`/`cargo test` 不会更新 debug 二进制**：验证时旧 `target/debug/qhud` 曾报告旧载荷。纠正措施：任何基于 `--dump` 的声明前先 `cargo build`。

## 周期 4 — 选择问题历程（2026-08-11 → 14，v0.5.1）

<!-- qhud:anchor -->
<a id="what-worked-2"></a>

### 有效做法

- **先测量再推理，然后让测量说话**：捕获阶段 ptr: 记录将“选择无效”的四种矛盾假设变成一眼可见的事实：每次点击都到达，但没有一次落在卡片上。发现两项真实修复：配额行可选择、重复幽灵监听器；没有这些记录就不可能发现第三原因。
- **在故障实例上实机实验，而非先重启**：xwd 像素哈希证明冻结，DOM 时钟重绘但帧逐字节相同；外部缩放证明抖动无效（D-008）；取消映射/重新映射证明恢复。每次实验都在错误修复发布前排除一类方案。
- **测量症状胜过诊断机制。** 两次渲染层尝试失败后，像素守卫通过哈希自身页脚、静止时恢复，在一个下午结束这类 bug；首次 22 h 无感恢复三次真实冻结。

<!-- qhud:anchor -->
<a id="what-to-fix-next-cycle-3"></a>

### 下个周期要改进

- **操作者报告与日志互相矛盾，但两者都正确。** “点击没反应”加“每次点击日志都正常”就是画面呈现冻结特征；下次先哈希像素，不要等第三天。纠正措施：检查现是 RUNBOOK 一行，守卫永久执行。
- **无法验证的缓解被两次宣称“已修复”**：关闭 DMABUF、关闭合成，因触发无法按需复现。两者数小时内复发。纠正措施：不能复现触发时，应说“已部署缓解，尚未验证”；优先检测加恢复，无需完全理解触发。
- **rAF 不是呈现。** 软件渲染时，没有任何内容到屏幕，rAF 仍触发；依赖它的 JS 看门狗在真实冻结期间失明。页内信号不能监管窗口自身可见性。

## 周期 5 — 两天静默失效的 ⟳（2026-09-01 → 09-04，v0.5.3）

<!-- qhud:anchor -->
<a id="what-worked-3"></a>

### 有效做法

- **已发布诊断一次找到原因。** `QHUD_EXTRA_DIAG=1
  qhud --claude-usage` 因 v0.5.0 格式问题而存在，本次一次调用就回答：两个子对象正常输出，证明响应是合法 JSON，将怀疑从“死令牌/空响应”转向“一个字段类型”。为旧问题构建的诊断在新问题上产生价值。
- **局部失败保持局部，让组件诚实。** 默认账户数字旧了两天，配额区如实标注日期，时间说明不断增长，而非空白或冒充实时。FR-20 时间标注和 D-015 局部错误规则，使两天中断只是烦恼，没有变成错误数字。
- **测试逐字采用实机响应。** 失败测试使用真实 09-03 响应，因此回归锚定现实，而非手写近似。

<!-- qhud:anchor -->
<a id="what-to-fix-next-cycle-4"></a>

### 下个周期要改进

- **没有字段名的“Did not parse”耗费两天。** 周期 3 已在 Codex 学过：`a937a3b` 中 HTTP 200 加“no data”隐藏两个 bug，响应预览诊断了两者；Claude 路径却再次发布相同盲错误。纠正措施：所有面向操作者的解析失败都携带解析器自己的信息（D-019）；通用教训是**拒绝必须说明拒绝了什么**，值得检查其他获取路径中裸 `ok_or_else` 拒绝。
- **一个可选字段绝不能使整个响应失败。** 5h/7d 窗口与 `used_credits` 无关，却一起丢失。纠正措施：整数语义数字经过宽容读取器；供应商响应新字段必须假定会按供应商这周任意选择的格式到达。
- **文档现场统计落后五倍。** v0.5.2 从守卫最初几天记录“截至 08-17 四次冻结”；journal 全覆盖 08-26 → 09-04 显示 21 次，全部重新映射恢复，显示器睡眠后数分钟内成簇。无人察觉，因为恢复不可见，这正是 D-017 目的；也说明自动恢复子系统必须主动读取计数，而不是等人偶然查看。纠正措施：统计现为 DASHBOARD 一行。
