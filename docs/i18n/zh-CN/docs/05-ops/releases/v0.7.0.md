qhud v0.7.0 在现有账户与会话视图下方加入低调的系统用量图表，
并新增用于确认运行构建的 About 面板。

- **小巧且清晰的历史。** CPU、MEM、受支持 GPU、DISK 和 NET 每 2 秒更新，
  保留最近约一分钟的最多 30 个样本。选择指标打开详情，再次选择可折叠，
  也支持 Tab + Enter/Space。百分比图表保持 0–100% 固定刻度；
  吞吐量图表随近期读取/写入或接收/发送速率调整。
- **明确的测量范围。** 磁盘速率汇总物理设备，不重复累加分区或堆叠设备 I/O。
  容量详情显示按卷去重的已挂载本地容量，每 30 秒更新。
  网络汇总具有可用 IP 地址的非回环接口，Linux 还会排除 down 接口；
  VPN、虚拟和物理接口可能重复计算同一流量。
- **可测量时显示 GPU。** Windows 使用 WDDM GPU Engine 计数器，取适配器中
  最繁忙的引擎。Linux 支持 AMD 可用的 sysfs busy 计数器，以及通过已安装 NVML
  读取 NVIDIA。首次有效采样时选定一个适配器，并在本次采样会话中保持选择。
  Linux 显存详情仅在数据源提供时显示；Windows 显存和其他不支持的 GPU 来源
  保持不可用。
- **安静采样。** 窗口隐藏或最小化时暂停系统测量。重新显示后开始新的历史并
  预热速率基线。缺失计数器、首次速率采样和重置显示缺口/`--`，
  有效空闲显示为零。数据只保存在内存中，不向外发送；系统采集使用本地 API，
  不扫描进程或启动监控命令。
- **关于与诊断。** 点击左上角 **qhud** 可查看内嵌版本、作者
  **Chenghao Quan (chquandogong)**、
  [主页](https://chquandogong.github.io/CHENGHAO-QUAN/)和仓库。
  `qhud --system-dump` 采集两次本地系统样本并输出 JSON，不读取账户或打开
  组件窗口。显式演示模式使用合成系统数据。

图表中没有 GPU 列表示未获得受支持的读数，不代表计算机没有 GPU。
曾经支持的 GPU 暂时读取失败时，该列保持显示并留下缺口。
这些是整机汇总指标，不是各代理的资源成本。

发布仍须通过 Windows 和 Ubuntu 的测试与构建。
Windows x64 ZIP 和 Linux x86_64 tarball 均附 SHA-256 文件。
现有账户配置继续保留在便携归档之外。
