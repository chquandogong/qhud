qhud v0.7.1 在 Linux 上测量 Intel GPU。v0.7.0 加入了 GPU 列，但没有任何 Linux
数据源覆盖 Intel 显卡，因此在只有 Intel GPU 的机器上该列始终为空。

- **空闲驻留的补集。** i915 与 xe 驱动不提供 busy 百分比，而是提供相反的数据：
  按 GT 统计其处于断电状态毫秒数的单调计数器。qhud 读取该计数器，并以采样窗口内
  的补集作为利用率。
- **取最繁忙的 GT，而非求和。** 同一显卡的各 GT（渲染、媒体）并行工作，
  因此由最繁忙的 GT 代表该适配器。这与 Windows 引擎计数器的规则一致。
- **缺口仍是缺口。** 显卡的首次读取没有可比较的窗口，因此不报告任何值，
  与磁盘和网络速率的首个样本相同。休眠或驱动重载导致计数器重置时保持缺口，
  而不是虚构的 100%。真正空闲的 GT 仍显示为零。
- **不提供显存。** 这些 GPU 使用 MEM 已经报告的共享系统内存，两个驱动在此
  都不提供显存总量。

已经提供 busy 百分比的设备保持不变：amdgpu 继续使用 sysfs 值，NVIDIA 继续使用
NVML。没有可读计数器的 Intel 显卡视为无法测量而非空闲，不会进入状态条。

已在 Ubuntu 24.04 上使用 Intel Arc（Meteor Lake，i915，两个 GT）验证：报告的
24.8% 与同一窗口内独立计算的 rc6 驻留值完全一致，实时挂件在 CPU、MEM、DISK 和
NET 旁显示了带历史的 GPU 列。发布仍以 Windows 与 Ubuntu 的测试和构建为门槛。
