qhud v0.7.3 为 Codex 方案徽标显示当前产品名称，并打包 v0.7.2 之后完成的安全、
依赖、发布与翻译工作。

- **当前 Codex 方案名称。** 经过核对的传输值 `prolite`、`pro`、`promax` 现在分别显示为
  **Pro 100**、**Pro 200**、**Pro 500**。该映射遵循 Codex 上游的
  [传输枚举](https://github.com/openai/codex/blob/f70810bcd210ed780a3da5940e9e60f74ac8ee60/codex-rs/protocol/src/auth.rs#L73-L95)、
  [订阅标签](https://github.com/openai/codex/blob/f70810bcd210ed780a3da5940e9e60f74ac8ee60/codex-rs/tui/src/subscription.rs#L10-L19)和
  [回归用例](https://github.com/openai/codex/blob/f70810bcd210ed780a3da5940e9e60f74ac8ee60/codex-rs/tui/src/status/helpers.rs#L200-L221)。
  `accounts.json` 中显式设置的方案标签仍是最高优先级的显示 override。未知供应商值会保留在
  详情文本中，但不会成为面向用户的徽标。
- **安全门禁与脱敏错误。** cargo-deny 作业现在检查锁定 Rust 依赖图中的通告、许可证和来源。
  该依赖图包含修复 RUSTSEC-2026-0285 的 rustls 0.23.45。其余日常库失败改用有界的类型化
  类别，不再复制可能含有 URL、路径或终端多路复用器输出的上游原文。
- **门禁发布资产。** 发布现在包含 CycloneDX 1.5 JSON SBOM、SHA-256 配套文件与来源证明。
  发布作业通过列出 release 可靠地续接草稿，验证资产恰好为 6 个，并拒绝内容不匹配或
  意外文件。`codex/**` 工作不再因分支 push 与 PR 各运行一次，而是只通过 PR 运行一次 CI。
- **依赖与翻译。** 包含 base64 0.23、libloading 0.9、reqwest 0.13.5 与 toml 1.1.6。
  仓库现在规定哪些英文文档需要完整的韩语和简体中文镜像，并在 CI 中检查其事实和修改覆盖。

自动 JavaScript 回归测试覆盖三项精确方案映射、大小写与首尾空格规范化、显式 override
优先级，以及未知传输值的隐藏。发布前尚未执行真实桌面方案徽标验证。2026-10-01 的
发布后 Windows 原生验证确认了公开 ZIP 的 SHA-256
`d6268bfd696e2a9c8b17d77a6590bfb11df18d73498e9d96f627998114183d4f`、
原始 `pro` 显示为 **Pro 200**、可执行文件和 About 的版本为 0.7.3，以及 CPU、内存、
GPU、磁盘和网络的渲染。检查了一张私有本地截图，随后将其删除；带日期的记录见
[`TEST_PLAN.md`](../../04-quality/TEST_PLAN.md)。
