# 架构 — qhud

> 状态：持续维护（根据 v0.6.0 源码从头重写） · 日期：2026-09-07 · 负责人：chquandogong
> 与 SPEC（必须做什么）及 DECISION_LOG（为何这样构建）配套。本文每项声明均依据 `v0.6.1` 代码树；行数和测试数也来自该代码树。

<!-- qhud:anchor -->
<a id="1-what-qhud-is-structurally"></a>

## 1. qhud 的结构

一个单进程 Tauri v2 桌面应用：Rust 核心负责观测和获取数据，无打包器的 Web 前端负责渲染。它是 qmonster 观测流水线的**第二前端**（D-001），以固定 Git revision 将该 crate 链接为库，从不写入其状态。

两个平台，一套代码：

| | Linux（参考平台） | Windows x64 |
| --- | --- | --- |
| Webview | 通过 GTK 3 使用 WebKitGTK | WebView2（必须有 Edge runtime） |
| 桌面层 | XWayland + EWMH `_NET_WM_STATE_BELOW`/`STICKY`（D-003） | 原生 always-on-bottom |
| 终端窗格 | 通过 qmonster 使用 tmux 或 herdr（D-007） | **未实现**，仅账户配额 |
| 帧守卫 | 启用（GTK 像素采样，D-017） | 编译时排除；WebView2 没有同类故障 |
| 依赖 | 普通 Git 固定依赖，无需同级检出目录 | 对同级检出目录应用仅作用于命令的补丁 |

Windows 移植没有增加第二条数据代码路径：供应商、解析、合并和渲染均共享，只有路径解析、进程创建和帧守卫按平台编译。

<!-- qhud:anchor -->
<a id="2-process-and-thread-model"></a>

## 2. 进程与线程模型

`main()` 依次执行：

1. **仅 Linux 的环境变量强制设置**，在线程创建前完成。三组仅在未设置时赋值的配置各有退出开关：`GDK_BACKEND=x11`（`QHUD_NO_X11_FORCE`）、`WEBKIT_DISABLE_DMABUF_RENDERER=1`（`QHUD_KEEP_DMABUF`）、`WEBKIT_DISABLE_COMPOSITING_MODE=1`（`QHUD_KEEP_COMPOSITING`）。任何值，包括空值，都算已设置。Windows 完全不包含这段代码。
2. **Argv 预处理**。在 Tauri 或 GTK 初始化前处理诊断及转发标志，因此诊断运行不会创建窗口。`--respawned` 先等待 1.5 s，避免重新执行被单实例守卫拦截。
3. **Tauri builder**，按注册顺序依次加入单实例插件（同时充当 argv 转发通道）、五个命令、窗口状态插件，然后是 `setup`。
4. **`setup`**：取得 `main` 窗口（缺失则立即 panic，因为该标签是构建时契约），重新设置 `tauri.conf.json` 已请求的层级状态（X11 只有在原生窗口实际创建后才遵循），创建托盘（失败仅记录，不致命），创建轮询线程。
5. `run()`：主线程进入 GTK 或 WebView2 事件循环。

只显式创建一个线程，即轮询循环。所有涉及窗口的操作都在主线程执行，包括通过 `run_on_main_thread` 调度采样的帧守卫。`fetch_*` 命令为 `async`，运行在 Tauri 运行时；独立诊断标志各自创建 Tokio 运行时，然后退出。

<!-- qhud:anchor -->
<a id="3-tray-and-the-layer-state-machine"></a>

## 3. 托盘与层级状态机

托盘菜单为 `Show / Hide`、`Pin above windows`（复选项）、`Reset position`、`Quit qhud`。置顶状态保存在进程级原子变量中：false 表示默认桌面层 keep-below，true 表示置顶。

应用层级时，除了切换底部/顶部，还总会重新设置跨工作区固定、跳过任务栏及可见性，随后发出 `qhud://layer`，记录 `qhud ui: layer:pinned` 或 `qhud ui: layer:below`。帧守卫恢复后也调用同一逻辑，因此重新映射不会静默丢失操作者的置顶选择。`Reset position` 用于处理拔掉显示器后，几何恢复仍指向已断开的屏幕（CV-1）。

<!-- qhud:anchor -->
<a id="4-the-poll-loop"></a>

## 4. 轮询循环

周期为 2 s。每轮依次：增加计数；每第 15 轮保存窗口几何检查点（窗口状态插件只在正常退出时保存，而小组件通常因信号或注销结束）；若未连接实时多路复用器且距上次尝试至少 10 s，则重新探测；观测；选择并补充数据载荷；发出 `qhud://report`；运行帧守卫；休眠。

**后端选择**（D-007）。qmonster 自带的 `auto` 通过仅在 herdr 窗格**内部**存在的环境变量发现 herdr，而 qhud 通常在所有窗格外运行。因此配置为 `auto` 且 `HERDR_ENV` 与 `HERDR_SOCKET_PATH` 均不存在时，qhud 创建两个候选，**先尝试 herdr，再尝试 tmux**；显式指定的 `[mux] backend` 则原样使用。候选必须成功完成一次验证性观测才能采用，报告的后端标签来自最终解析的来源，而非请求它的配置。配置读取自 `~/.qmonster/config/qmonster.toml`；解析失败会记录日志并回退到 serde 默认值。

**没有多路复用器不再意味着演示。** v0.6.0 之前，无 mux 启动会渲染演示夹具。现在渲染真实本地载荷：零窗格、`source = "local"`，加上所有可在本地发现的账户身份及 qhud 保存的带时间快照，缺失用量保持缺失，不填零。示例数据必须通过 `--demo` 启用，并完全关闭实时探测。两项测试守住这一界限：无 mux 时不虚构用量；只有额外账户有行时，默认账户仍可访问。

补充顺序固定：检测账户、附加已保存快照、附加账户、附加只有身份的行、附加占位行，最后重新计算摘要的五小时最大值。只有身份的行让没有保存读数的账户仍然显示，从而始终提供可用的刷新控件。

**归属检查。** 只有快照的账户 id 或邮箱与当前登录匹配时才使用，避免上一登录较新的读数掩盖当前登录较旧的读数，这正是 v0.6.0 修复的故障。已保存 Codex 工作区的 `active` 标志也会根据当前账户重新计算，而不信任磁盘值。

**降级。** 无配置时使用默认值；一个后端失败则继续尝试下一个；全部失败则回退本地载荷并每 10 s 重试；运行中失去实时来源则回退本地载荷，保留真实账户和保存的用量；按设计忽略事件发出和几何保存失败。

<a id="5-paths"></a>

## 5. 路径

`paths.rs`（v0.6.0 新增）集中解析所有存储位置，所有查找均将空环境变量视为未设置。

| 对象 | 解析顺序 |
| --- | --- |
| 主目录 | Windows：`USERPROFILE` 然后 `HOME`；其他平台：`HOME` 然后 `USERPROFILE`。 |
| qhud 配置 | 原样使用 `QHUD_CONFIG_DIR` → `XDG_CONFIG_HOME/qhud`（两个平台）→ Windows 上若旧 `~/.config/qhud` 已存在则使用，否则 `APPDATA/qhud` → 其他情况 `~/.config/qhud` |
| Codex 主目录 | `CODEX_HOME` → `~/.codex` |
| Claude 配置目录 | `CLAUDE_CONFIG_DIR` → `~/.claude` |
| Claude 配置文件 | `CLAUDE_CONFIG_DIR/.claude.json` → `~/.claude.json` |

Windows 的主目录优先级是有意设计的：Git-Bash 风格的 `HOME` 不得覆盖原生用户目录。配置目录顺序也是如此：已存在的 `~/.config/qhud` 继续有效，不会因迁移到 `APPDATA` 而被遗弃。

核心还读取这些环境变量：用于发现 Codex CLI 的 `QHUD_CODEX_BIN`、`LOCALAPPDATA` 和 `PATH`，用于 Windows 辅助进程的 `SystemRoot`，以及用于无身份信息 Claude 响应诊断的 `QHUD_EXTRA_DIAG`。

<a id="6-frame-guard-linux-only-d-017"></a>

## 6. 帧守卫（仅 Linux，D-017）

每第 14 轮，即约 28 s，小组件会对自己的窗口像素条计算哈希：从 GdkWindow 读取底部 24 像素高、最多 420 像素宽的区域。那里页脚时钟每秒重绘，因此像素逐字节相同意味着合成器没有呈现新帧。

恢复阶梯有两级，并可重置：哈希变化会清除进行中的恢复状态；一次静态样本触发隐藏再显示并重新设置层级；第二次静态样本以 `--respawned` 重新执行进程；第三次不再操作，因为重启已经进行。隐藏窗口会重置状态而非触发恢复，因为不可见时像素静止是合理的。会话首次成功采样记录 `qhud: frame guard armed (first pixel sample ok)`，证明采样器本身有效，避免将静默失效的采样器误认为屏幕健康。

哈希使用 FNV-1a 64 位，并做一项调整：结果为零时映射为一，因为零保留作“尚未采样”的哨兵值。

非 Linux 构建会编译排除整个机制；决策逻辑仍可在所有平台进行单元测试。

<a id="7-window-and-capability-surface"></a>

## 7. 窗口与权限范围

窗口为 392×520，无装饰、透明、始终在底部、跳过任务栏、在所有工作区可见、可调整大小，最小 320×200。不声明初始位置，几何信息来自窗口状态插件。前端无打包器，因此使用 `withGlobalTauri`；内容安全策略仅允许 self、内联样式及 data-URI 图片。

权限刻意保持最少并逐项枚举：默认权限，加上光标位置、webview 缩放、设置位置和大小，以及窗口状态插件的权限集。拖动、调整大小和缩放等所有自身操作都使用这四个窗口权限完成，不委托合成器（D-008）。

`bundle.active` 为 false：发布的是压缩包中的原始二进制，不是安装程序（D-006）。

<a id="8-build-and-release"></a>

## 8. 构建与发布

一个 CI 工作流，两个平台作业，每次推送到 `main` 和每个 pull request 都执行：

- **Ubuntu 24.04**：`cargo fmt --all --check`、`cargo clippy --locked
--all-targets -- -D warnings`、`cargo test --locked --all-targets`、`cargo
build --locked --release`。
- **Windows 2022**：以测试模式运行 Windows 构建脚本，然后对 `Cargo.toml` 和 `Cargo.lock` 执行 `git diff --exit-code`，证明规范依赖文件已逐字节恢复。

发布工作流由任何 `v*` 标签触发，再次执行两个平台的构建和测试，分别打包 Linux tarball 和 Windows ZIP，附带 SHA-256 文件及构建来源证明，只有两个作业通过才发布。发布步骤要求存在 `docs/05-ops/releases/<tag>.md`；缺少书面说明的发布会失败，而不是不作解释地发出。

**Windows 依赖补丁**存在的原因是，固定版本的 qmonster 在 GUI 进程中会弹出控制台窗口，并含有假定 Unix 环境的测试。补丁添加一个辅助函数，仅在 Windows 应用 `CREATE_NO_WINDOW`，其他平台不变；所有进程探测位置均经由该函数，并对 Unix 专用测试加条件编译。补丁仅应用于 qhud 代码树外的同级检出目录，通过临时 `cargo --config` patch 表接入，随后删除；同时移除已验证的一个 `Cargo.lock` 行，在 `finally` 中逐字节恢复。因此普通 Linux `cargo build` 仍从 Git 解析 qmonster，不需要同级检出目录或补丁。

release 配置——`strip`、`lto`、`codegen-units = 1`——位于工作区根清单。直到 v0.6.0 之前它一直放在成员清单中，Cargo 会忽略那里，因此此前每次发布都提供了未优化体积的二进制：v0.5.3 为 25.13 MiB，v0.6.0 为 15.07 MiB。Cargo 为此在每次构建时警告了整整一个月。

<a id="9-the-payload-contract"></a>

## 9. 数据载荷契约

一个 `qhud://report` 事件承载前端知道的一切。核心将 qmonster 丰富的窗格报告重新序列化为精简的显示载荷，因此 webview 不接触上游类型，上游重构只涉及一个文件。此边界固定完成两种转换：压力以 0..1 比例进入、整数百分比输出；重置时刻以 Unix 秒输出，由前端渲染倒计时。

schema 版本为 1，历次发布始终为 1：只增加字段，通常为空的新增字段省略，而不发送 null。

```
schema, source, backend, generated_at_ms, poll_secs
quotas[]   provider, h5, d7, from_label, session, account?, origin?,
           cache_fetched_at_ms?, scoped[]?, extra?
panes[]    pane_id, label, session, provider, status, status_label,
           elapsed_secs, cli_version, update_hint, model, effort, branch,
           cwd, mem, cost_usd, flags[], gauges{ctx,h5,d7}, conflicts[]
summary    panes, conflicts, max_5h_pct
account_placeholders[]?, workspace_names{}?, workspace_plans{}?,
codex_workspaces[]?, codex_fetched_at_ms?
```

`source` 为 `live`、`local` 或 `demo`。多路复用器提供载荷时，`backend` 为 `herdr` 或 `tmux`，否则为 null。仪表是 `{pct, source,
reset_unix, of_tokens}`；`origin` 为 `pane`、`cache` 或 `fetched`，前端据此决定一行是否可以呈现为实时。

`qhud --dump` 会将完全相同的载荷输出为格式化 JSON，因此运维手册用该命令，而不是截图，回答“你怀疑某个数字吗”。

<a id="10-merge-rules"></a>

## 10. 合并规则

同一事实可能从最多三个来源、以不同新旧程度抵达 qhud，这些规则确保小组件不会把旧值当作当前值。

**按供应商汇总。** 配额属于账户，不属于窗格（D-011），因此同一供应商的窗格合并为一行；每个窗口取最高百分比，因为窗口内用量只会增长，每个窗格读数都是下界，最大值最新。五小时窗口胜出的窗格也提供该行的来源归属；仅当五小时窗口缺失时才使用七日胜出者。

**排除已过期快照，宽限 90 秒。** 重置时刻已过去的读数描述的是不再存在的窗口，否则空闲窗格昨天的 88% 会永远压过今天真实的 12%。宽限存在是因为重置前瞬间取得的读数，在很短时间内仍可诚实描述新窗口。若某个窗口的全部读数都过期，则整个窗口省略；不显示优于显示错误信息。

**实时窗格读数绝不被覆盖。** 保存的快照可以补齐窗格没有的窗口，附加只有快照包含的模型窗口和支出，并标注自身时间，但不能替换窗格报告的数字。填补空缺不等于覆盖。

**没有窗格的供应商仍有一行**，由快照生成并标记快照来源。这正是持久化层的目的：没有 CLI 运行时数字仍保留。自 v0.6.0 起，生成门槛降低：仅含模型独立配额池或仅含额外支出的快照仍是真实读数，现在也会生成行，不再因缺少主窗口而丢弃。

**先检查归属，再比较时间。** 只有属于当前登录账户的快照才被采用。先比较新旧会让上一登录较新的读数掩盖当前登录较旧的读数，v0.6.0 已修复。保存的 Codex 工作区也出于同一原因，根据当前登录重新计算 active 标志。

**一个账户的数字绝不使用另一个账户的名字。** 只给尚无身份的行附加身份，因为额外账户行自带身份；当前 Codex 工作区并入供应商行，不重复呈现时间略有偏差的同一个周窗口。

<a id="11-window-vocabulary"></a>

## 11. 窗口术语

界面所有地方均按持续时间命名窗口：5H、1D、7D、30D，只在前端一张表中转换。Codex 传输数据使用“weekly”和“30d”，操作者合理地问“weekly”和“7D”是否不同；它们是同一个七日滚动窗口，因此使用同一个名字。

在传输层，Codex 窗口标签根据**时长**推导，绝不根据 primary/secondary 通道。参考机器已验证：2026-07-13 前 primary 是五小时、secondary 是每周；之后 primary 变为每周，secondary 为 null，并出现三十日窗口。Codex 自身按时长命名，qhud 也如此，允许百分之十的容差，无法识别时回退到分钟数。

模型独立池可能与主池时长相同，因此 scope **名称**是两个 7D 标签唯一的区别。scope 从各供应商自己的字段，经载荷一直传递到渲染标签；未知配额池类型退化为提示中的一行，而非消失。

<!-- qhud:anchor -->
<a id="12-the-frontend"></a>

## 12. 前端

没有框架和打包器：原地更新 DOM，2 s 刷新不会重新启动 CSS 过渡；整个应用是一个文件，通过 Tauri 资源协议和 `withGlobalTauri` 提供。

**渲染顺序**：摘要、演示标签、全部刷新状态，然后是配额区（分组、行、Codex 子行、折叠占位行），其外层 try/catch 将任何异常转发到 stderr；接着按载荷顺序以键控方式更新卡片，最后是页脚。以前前端异常在 webview 外不可见，曾因此发布过失效的配额区。

**配额区的行身份为（供应商、账户、组织）**，与核心去重键相同（D-018）。新行插入在该供应商最后一行之后，因此第二个账户不会把分组标题挤乱。供应商作为最外层，是因为操作者在决定下一任务在哪里运行时先选择它；它与窗格术语一致，且恰好只有三个，因此账户增多时浏览路径仍稳定。

**始终显示新旧程度和来源。** 只有快照来源的行附带时间说明；实时行中，快照只贡献模型窗口，若给整行标记会误导用户认为可见仪表都已陈旧。来自快照的模型标签会变暗并加标识，因为限定 scope 的仪表只能来自缓存，不得看起来像当前值；v0.4.0 曾发生缓存 5% 出现在实时仪表旁，而真实值已是 22% 的问题。

**三个独立获取状态机**，每个供应商一个，均为 idle → loading → done 或 error，各有独立错误呈现，因此一个供应商的 401 不会隐藏另一个的数字。全部刷新控件反映它们状态的并集。实时结果按配置目录**和**账户 id 匹配行；v0.6.0 加入账户 id 这一联合条件，防止刷新结果落到错误的行。

**选择会原地展开行。** 对很少指向的底层窗口而言，悬停提示几乎没有机会出现，因此点击后将信息放到行内；网络只由刷新控件触发，选择行绝不发起请求。所有交互绑定 `pointerdown`，不绑定 `click`，因为该 webview 能可靠派发 pointerdown，却不会合成 click（D-009）。

**窗口几何由自身驱动**（D-008）。合成器交互式移动和缩放对底层 XWayland 窗口不可靠，且窗口移动时 webview 的屏幕坐标会陈旧。因此 requestAnimationFrame 循环读取 Tauri 全局光标位置，直接设置位置或大小；指针事件只负责启停循环。刻意不使用窗口报告的位置和大小，因为工具包对无装饰 X11 窗口会产生一个虚构边框高度的误报。Ctrl+滚轮缩放范围为 70–160%，并持久化；小组件从不取得键盘焦点。

**可观测性是有意设计的。** 事件记录通过一个命令送到 stderr，是判断渲染逻辑是否执行的唯一可用证据：配额区生成了什么、每条身份行及仪表标签的实际文本、每次真实 pointerdown 及落点、选择变化、缩放、任何 JavaScript 错误。只有计数不够，窗口**名称**错误恰是计数抓不到的 bug；这些也都不能证明像素已绘制，因此需要帧守卫。

一秒一次的计时器重绘倒计时；八秒没有新载荷时将页脚标记为停滞，让已停止的后端如实说明状态，而不是冻结看似合理的数字（CV-2）。

**持久化位置。** 选中窗格、占位区展开状态和缩放保存在浏览器存储中，外层封装可容忍存储完全被拒绝；窗口几何由窗口状态插件保存，轮询循环每 30 s 建立检查点。

<a id="14-providers"></a>

## 14. 供应商

两个问题决定供应商路径的一切：数据是否无需请求就会到达，以及凭据由谁持有。

| | 被动，每 2 s | 显式刷新时 | 凭据保管 |
| --- | --- | --- | --- |
| Claude | 通过 qmonster 取得状态行；Claude Code 自有磁盘用量缓存；从 `.claude.json` 取得身份 | `GET https://api.anthropic.com/api/oauth/usage`，每个已登录配置目录一次 | qhud 为 HTTP 请求读取现有 access token |
| Codex | 当前登录的窗格状态行；从 `auth.json` 取得身份 | 每份保存凭据先访问 `wham/accounts/check` 再访问 `wham/usage`；当前登录失败时，短生命周期 `codex app-server` 子进程通过 stdio 回答 | HTTP 路径由 qhud 读取 access token；回退路径全部由 CLI 管理 |
| agy | 有窗格时使用窗格状态行；从 `google_accounts.json` 取得身份 | 向正在运行的 agy 进程发送环回 Connect RPC，无令牌和 CSRF | agy 自身；qhud 完全不读取凭据 |

三条规则适用于所有路径（D-014、D-016）：

- **绝不用定时器触发。** 轮询只读取本地文件和多路复用器。每个离开机器的字节都源自操作者请求。
- **绝不执行 refresh grant。** Codex refresh token 单次使用并轮换；未保存轮换结果会破坏操作者登录。也不与 Claude 的刷新竞争，因为与 Claude Code 自身刷新竞争同样会破坏登录。
- **优先委托。** 供应商自身进程能够回答时，就让它回答，使令牌轮换和钥匙串凭据由供应商负责。

**Claude。** 每次调用重新读取凭据，只读 access token，不读旁边的 refresh token。User-Agent 是关键条件：没有真实 `claude-code/<version>` 时，端点返回 429 且没有重试提示。身份来自配置目录自己的文件，绝不来自响应；响应包含账户 uuid 和邮箱，从不记录，唯一例外是环境变量控制的诊断，只输出两个不含身份信息的子对象，用于分析格式漂移。一次刷新遍历默认账户及全部注册额外配置目录，分别写入各自存储键，局部失败保持局部：额外账户过期不能隐藏默认账户数字。拒绝响应时输出 serde 自带的字段和类型信息，其设计保证不含身份；因为没有字段名的“did not parse”曾让诊断耗时两天（D-019）。

**Codex。** 读取每个注册主目录中的 `auth.json` 和停放的同级文件，按账户 id 去重，将当前文件排在最前以确保优先。每份凭据读取自己的工作区：服务器拒绝将一个令牌重新限定到另一工作区，因此响应账户与请求不同则丢弃并记录不匹配，不错误贴标签。窗口标签来自**时长**，不来自 primary/secondary 通道。当前登录的 HTTP 路径失败时，以只读及 on-request 批准设置创建 `codex app-server` 子进程，经 stdio 传入三行 JSON-RPC 握手，刻意保持 stdin 打开——服务器在 EOF 时退出，可能尚未回答——并在 25 秒后超时终止。自 v0.6.0 起，按限额映射可缺失、为 null 或为空，顶层池也可为 null；任一单独存在即可，主池恰好消费一次，避免同一周窗口显示两次，顶层 null 也不能隐藏真实模型读数。

**agy。** 正在运行的 agy 绑定环回监听器，无需令牌和 CSRF 即可回答配额摘要。从操作系统自身表中发现端口：Linux 将 agy 进程 socket inode 与 `/proc/net/tcp` 环回监听器关联；Windows 使用隐藏 PowerShell 查询，其脚本仅返回端口号。依序尝试候选；HTTPS 监听器拒绝普通 HTTP，因而自行被排除。传输格式为省略默认值的 proto3 JSON，缺少剩余比例意味着已无剩余，绝不解释为“未知，算正常”。读数附带刷新开始时的身份，因此之后登录不会重贴保存快照的身份标签。

<a id="15-parsing-and-the-snapshot-shape"></a>

## 15. 解析与快照结构

所有供应商共用一个结构：两个主窗口、限定 scope 窗口列表、可选支出，渲染器无需第二条代码路径。Claude 磁盘缓存及 qhud 自己的刷新结果直接解析为该结构；Codex 工作区和 agy 配额池映射为它。

三条解析规则各有必要：

- **缺少百分比表示“没有此限额”，不是零。** 无该窗口的套餐会报告 null，将其显示为 0% 会错误声称未使用，而实际并不存在该上限。缺 kind 或百分比的限额被丢弃，不填零；当前响应缺少的模型从显示中移除，而非显示 0%。
- **按语义读取整数语义数字**（D-019）。整数值浮点数就是该整数；带小数的浮点数因单位歧义而丢弃，猜测单位可能把五十美元显示为五十美分。两种情况均不得使外层响应失败。
- **金额不得经浮点数往返转换。** 支出使用最小货币单位、币种和指数；两个传输对象按字段选取更丰富的值，而非二选一，因为只有其中一个提供 limit-reached 标志。

Claude Code 自有缓存和 qhud 最近刷新均存在时，较新者优先；时间相同时 qhud 自己的读取优先，因为其完整度至少相同。无论采用哪一个，行上都标注来源和时间。

<a id="16-identity"></a>

## 16. 身份

从 CLI 已维护的本地文件中选择身份字段，不发起供应商网络请求，也不使用令牌进行观测：Claude 配置文件、Codex `auth.json` 中的账户 id、agy 当前 Google 账户。已注销的供应商不提供任何行；任何不可读或格式错误的文件都只视为账户不存在，因为这是信息补充，绝不能使整轮失败。

**行身份是（账户、组织）这一对值**（D-018）。一个 claude.ai 登录可同时拥有团队席位和个人组织，两者为独立配额池；只有同一组织内的同一账户才重复。前端使用相同键，并以配置目录**和**账户 id 将刷新结果匹配到行，因为只匹配账户会把一个组织的数字送到同一登录的两行上。

显示名称由操作者提供，通过仓库外的注册表覆盖。绝不根据传输中的套餐字符串“修正”它：那些是供应商内部术语，不是操作者看到的名称。

<a id="17-registry-and-placeholders"></a>

## 17. 注册表与占位行

一个操作者拥有的文件保存显示标签、工作区名称和套餐、曾连接账户列表、已忽略项，以及支持多账户的额外 Claude 配置目录与 Codex 主目录（D-015）。

三条占位规则，按优先级排列：

1. 有效的实时凭据总会显示。当前事实绝不隐藏。
2. 已知账户若无实时凭据，显示占位行并提示如何恢复；其配额仍在变化，隐藏会造成事实遗漏。
3. 操作者明确忽略的账户绝不显示为占位行。忽略**不会**隐藏实时账户；若要如此，应注销。静默隐藏正在使用的账户是更严重的错误。

qhud 只写该文件中的一个键，即忽略列表，使用通用 JSON 而非类型化结构体编辑，以保留手工维护的键。格式错误内容视为空注册表；其信息都不足以成为使一轮失败的理由。

<a id="18-persistence"></a>

## 18. 持久化

两个文件均在仓库外，因为包含账户 id；均先写临时文件再重命名，因为轮询每轮重读，原地截断写入正是状态行旁路文件曾产生撕裂读取的原因。

- `accounts.json`：上述操作者注册表。
- `fetched-usage.json`：显式刷新结果，包括默认 Claude 账户、以配置目录为键的每个额外 Claude 账户、Codex 工作区及获取时间、agy。删除始终安全，下次刷新会重建。

垃圾内容、旧 schema、缺失文件均视为空存储；忽略未知字段，因此较新版本写出的存储不会破坏旧版本。

**并发刷新不能相互擦除。** 三个供应商同时刷新，v0.6.0 前各自独立加载、修改、保存，因此两个同时完成的刷新可能分别写入基于合并前读数建立的存储。现在从加载、合并到原子替换全程持有进程级锁。回归测试驱动八个经屏障同步的写入者，断言八份结果均保留。

qhud 不写入 qmonster 自身目录。该状态由 TUI 管理，第二个写入者会与其竞争（D-004）。

<a id="19-invariants"></a>

## 19. 不变量

以下规则均来自现场故障经验，每条在代码中执行，并由测试断言。

- **旧数字绝不能冒充当前值。** 快照来源行标注时间；缓存模型标签变暗并加标记；过期窗口省略。这条规则背后的 bug 是，某模型真实用量 22% 时，缓存 5% 却出现在实时仪表旁。
- **没有错误不能证明已绘制。** 事件记录证明逻辑，不证明像素；该区别曾耗费三天，因此需要像素守卫（D-010、D-017）。
- **一个事实一个名称，一个名称一个事实**（D-011）。各处均按时长命名窗口，scope 名称端到端传递，模型独立池不能被折叠进时长相同的主池。
- **缺失保持缺失。** 不填零，不虚构池，不为供应商未提及的模型合成 0%。
- **局部失败保持局部。** 一个供应商的 401 或一个过期额外账户，绝不隐藏另一个账户的数字。
- **轮询循环被动运行。** 仅本地文件及多路复用器；网络和 RPC 位于显式控件及对应命令行入口之后。
- **归属先于时间。** 快照只用于其所属账户。
- **qhud 不执行 OAuth refresh grant。** 观测选择身份字段，不使用供应商令牌。
