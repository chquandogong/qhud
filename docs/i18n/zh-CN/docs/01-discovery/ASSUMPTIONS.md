# 假设 — qhud

> 状态：持续维护 · 日期：2026-09-07 · 负责人：chquandogong
> 为 v0.6.1 重写。旧版清单源于 v0.4.0，包含过时的依赖 revision、被 v0.6.0 改变的单平台前提、对于 qhud 自有状态从未成立的“从不持久化”说法，以及一个月后已无法理解的相对日期“今天已验证”。本文始终使用绝对日期。

| ID | 假设 | 状态 | 证据 / 重新评估触发条件 |
| --- | --- | --- | --- |
| A1 | 主要**终端监控**目标是一台 GNOME Wayland 工作站。Windows x64 是受支持的**账户用量**目标，不观测窗格。其他桌面尽力支持；macOS 不在范围内 | 已接受，修订于 2026-09-07 | v0.6.0 新增原生 Windows 目标，具有独立 CI 作业、发布产物和运维指南。若出现 KDE 或 wlroots 用户，重新评估 layer-shell 路径的价值 |
| A2 | Mutter 会遵循 XWayland 窗口的 `_NET_WM_STATE_BELOW` 和 `_STICKY` | 已验证，2026-09-07 | 已对发布的 v0.6.0 Linux 产物重新验证：`_NET_WM_STATE` 包含 BELOW、STICKY、SKIP_TASKBAR 和 SKIP_PAGER，`_NET_WM_DESKTOP` 为 `0xFFFFFFFF`。最初来自可行性探针。仅适用于 Linux |
| A3 | 两台显示器均采用缩放比例 1，因此不存在 XWayland 分数缩放模糊 | 已验证，2026-09-07 | eDP-1 2560×1600 和 HDMI-1 3840×2160，均为 scale 1。启用分数缩放时重新评估：GNOME 46 会使 XWayland 模糊，GNOME 47+ 有改善（R3） |
| A4 | qmonster TUI 管理其目录下的一切；第二个写入者会与其数据库发生竞争 | 设计上已接受 | `NoopSink` 和 `SilentNotify`（D-004）。qhud 在其他位置持久化**自身**状态：注册表、获取结果存储、窗口几何信息，均在 qhud 配置目录中，先写临时文件再重命名。不变量是“不写入 `~/.qmonster`”，不是“完全不写入” |
| A5 | `src-tauri/Cargo.toml` 中固定 revision 的 qmonster 库 API 是契约；上游可能变化 | 已固定 | 不在正文重复写 revision：该行旧版曾写了一个被替代长达一个月的 revision。应有意识地升级，并重跑 `view.rs` 中的契约测试。Windows 使用同一 revision 加仓库内补丁，仅在该平台的 Cargo 命令中应用（D-020） |
| A6 | 告警由 TUI 和供应商负责；小组件再通知会重复触发 | 已接受 | `SilentNotify` |
| A7 | 演示数据足够接近设计稿，可作为视觉一致性夹具 | 已接受，范围收窄于 2026-09-07 | 作为夹具仍成立，且会运行生产用汇总逻辑。原假设另一半——无法连接多路复用器时，可以用演示数据代替——已在 v0.6.0 **撤回**：无 mux 启动现在显示真实账户，演示须使用 `--demo`（D-005） |
| A8 | X11 后端会遵循 `visibleOnAllWorkspaces` 和 `alwaysOnBottom` | 已验证，2026-09-07 | 窗口完成实现及每次层级切换后，代码都会重新设置，且已用 `xprop` 确认。没有对 Windows 作出同样声明，也不应凭空补充 |
| A9 | 页脚时钟每秒重绘，因此间隔 28 s 的像素条逐字节相同意味着合成器没有呈现新画面 | 关键前提，作为假设尚未验证 | 这是帧守卫的全部前提（D-017）。若页脚因合理原因停止跳动，守卫会误报，对健康窗口执行隐藏再显示。若页脚内容变为有条件显示，应重新评估 |
| A10 | 隐藏再显示可让冻结窗口恢复绘制 | 已实机验证一次，2026-08-13 | 已在真正冻结的实例上证明；此后现场的 28 次冻结均在这一恢复层级解决。**第二**层级——重新执行进程——从未在现场触发，因此只受单元测试覆盖 |
| A11 | 供应商 CLI 在文档说明的路径中以明文保存账户身份 | 已接受 | Claude 配置文件、Codex `auth.json` 中的账户 id、agy 的当前 Google 账户（D-013）。路径现可通过环境变量覆盖，因此假设针对字段名而非位置。若供应商将身份移入钥匙串，应重新评估；agy 的实时令牌已经如此，这也是 agy 多账户尚未实现的原因 |
| A12 | 当前 Codex 登录的工作区配额池与其窗格状态行报告的是同一配额池 | 已接受 | 因此该工作区合并到账户行，而非重复显示一个时间略有偏差的同一周配额窗口（v0.5.0）。若 Codex 开始报告不同于账户池的窗格池，应重新评估 |
| A13 | 所有 Windows 目标机器均有 Edge WebView2 Runtime | 必需，qhud 未验证 | 已列为前提条件；小组件不会检测或安装它（R15）。若 Windows 用户报告启动静默失败，应重新评估 |
| A14 | 供应商传输格式**不稳定**，任何整数类型字段都可能以其他形式到达 | 付出代价后接受，2026-09-01 | 这是反向假设：记录它是因为相信相反前提曾导致刷新失效两天。每个新加入的整数语义字段均须通过宽容读取器；任何一个可选字段都不得使整份响应失败（D-019、R14） |
