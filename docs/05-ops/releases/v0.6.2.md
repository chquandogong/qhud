qhud v0.6.2 automatically displays the Codex email available in local login data.
Previously, a new computer without an operator-supplied label showed a long
account/workspace ID even when the Codex ID token already contained the email.

- **Automatic email display.** Read the email from the local `auth.json`
  ID-token payload in the current Codex home (`CODEX_HOME` is respected). A normal login with
  an email no longer requires a per-computer `accounts.json` label mapping.
- **Existing overrides and account separation remain intact.** Operator labels
  take precedence over the email. Missing or malformed email/token data falls
  back to the account ID. Account/workspace IDs still determine identity and
  usage ownership; an email does not combine separate workspaces.
- **Local display only.** Email recognition makes no network requests, writes
  no credentials, and performs no OAuth refresh grants. The decoded email is a
  display hint, not a verified authentication claim.
- **Documentation in three languages.** The release includes the revised
  Korean-default README, complete English/Korean/Simplified Chinese documentation,
  and updated installation and email-display guidance.

Both platform test/build jobs must pass before publication. Windows x64 ZIP and
Linux x86_64 tarball downloads include SHA-256 checksum files. Credentials,
account settings, and operator labels are not included in release archives.
