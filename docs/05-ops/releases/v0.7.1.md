qhud v0.7.1 measures Intel GPUs on Linux. v0.7.0 added the GPU column, but no
Linux source covered Intel graphics, so the column stayed empty on machines whose
only GPU is an Intel one.

- **Idle residency, inverted.** The i915 and xe drivers publish no busy
  percentage. Both publish the opposite: a monotonic counter of the milliseconds
  each GT spent powered down. qhud reads that counter and reports its complement
  over the sampling window.
- **Busiest GT, never a sum.** A card's GTs — render, media — run in parallel, so
  the busiest one carries the adapter. This is the rule the Windows engine
  counters already follow.
- **Gaps stay gaps.** A card's first read has no window to measure and reports
  nothing, like the first disk and network rate samples. A counter reset from a
  suspend or a driver reload stays a gap rather than a fabricated 100%. A GT that
  was genuinely idle is still zero.
- **VRAM unavailable.** These GPUs render from shared system memory, which MEM
  already reports; neither driver publishes a VRAM total here.

Devices that already publish a busy percentage are untouched: amdgpu keeps its
sysfs reading and NVIDIA keeps NVML. An Intel card without a readable counter is
unmeasurable rather than idle, and stays out of the strip.

Verified on Ubuntu 24.04 against Intel Arc (Meteor Lake, i915, two GTs): the
reported 24.8% matched an independent rc6-residency computation over the same
window exactly, and the live widget showed the GPU column with history beside
CPU, MEM, DISK and NET. Publishing remains gated by the Windows and Ubuntu tests
and builds.
