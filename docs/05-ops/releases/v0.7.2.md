qhud v0.7.2 keeps a quota row's reset countdown when the live pane reading
carries none. It is also the first release to package the security work that
landed on `main` after v0.7.1.

- **Reset countdown kept.** A provider row merges the live pane reading with
  qhud's stored usage snapshot, and the pane's percentage still wins. Before,
  the pane gauge replaced the snapshot's gauge wholesale, reset time included,
  so an idle Codex pane reporting weekly 0% with no reset hid the countdown the
  last fetch already knew. A pane gauge without a reset now takes the
  snapshot's, but never one that has already gone by: that belongs to a closed
  window, and the row shows no countdown rather than a wrong one.
- **Dependency patch.** `quinn-proto` is locked at 0.11.17, addressing a remote
  memory-exhaustion advisory in the earlier revision.
- **Redacted ambient diagnostics.** Normal logs across the Codex, Claude,
  terminal-multiplexer, storage and frontend paths no longer carry account
  labels, IDs, paths, usage values or exception text. Explicit JSON dump
  commands remain operator-requested diagnostics; redact them before sharing.
- **Gated publication.** This is the first release cut from protected `main`
  through the protected-tag workflow: full CI gate, four assets with SHA-256
  files and build-provenance attestations, and a reviewed draft before
  publication.

Verified on Ubuntu 24.04 against the live session: with an idle Codex pane and
a Codex fetch from earlier the same day, `--dump` reported the weekly row with
the fetch's reset, and the restarted widget showed `7D 6% · 6d 20h` where it had
shown `0%` with no countdown. Windows shares the merge code but was not
re-exercised on hardware; its CI test and build remain the gate.
