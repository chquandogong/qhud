qhud v0.7.0 adds a subtle system-usage strip below the existing account and session
view, plus an About panel that identifies the running build.

- **Small, readable history.** CPU, MEM, optional GPU, DISK and NET update every
  2 seconds and retain up to 30 points from roughly the last minute. Select a
  metric for details; select it again to collapse. Keyboard Tab + Enter/Space
  also works. Percentage graphs keep a fixed 0–100% scale; throughput graphs
  adapt to recent read/write or receive/send rates.
- **Measurements with explicit boundaries.** Disk read/write speed covers physical
  devices without summing partitions or stacked-device I/O again. Storage details
  show deduplicated mounted local capacity, refreshed every 30 seconds. Network
  speed covers non-loopback interfaces with usable IP addresses (Linux also
  filters down interfaces); VPN/virtual and physical interfaces may count the
  same traffic twice.
- **GPU when measurable.** Windows uses WDDM GPU Engine counters and the busiest
  engine per adapter. Linux uses AMD's available sysfs busy counter and NVIDIA
  through installed NVML. One adapter is selected at the first valid sample and
  kept for the sampling session. Linux VRAM details appear only when supplied;
  Windows VRAM and other unsupported GPU sources remain unavailable.
- **Quiet sampling.** Hidden or minimized windows pause system measurements.
  Showing the window again starts a fresh history and warms up rates. Missing
  counters, initial rate samples and resets produce gaps/`--`; valid idle is
  zero. Data stays in memory and is not sent anywhere. System collection uses
  local APIs without scanning processes or launching monitoring commands.
- **About and diagnostics.** Click the top-left **qhud** name for the embedded
  version, maker **Chenghao Quan (chquandogong)**,
  [homepage](https://chquandogong.github.io/CHENGHAO-QUAN/) and repository.
  `qhud --system-dump` takes two local system samples and prints JSON without
  account reads or a widget window. Explicit demo mode uses synthetic system data.

GPU absence from the strip means no supported reading was obtained, not proof
that the computer has no GPU. After a supported GPU temporarily fails, its column
remains and shows a gap. These are machine totals, not per-agent resource costs.

Publishing remains gated by the Windows and Ubuntu tests/builds. Windows x64 ZIP
and Linux x86_64 tarball downloads include SHA-256 files. Existing account
configuration remains outside the portable archives.
